All Fabrik-managed apps deploy **exclusively** through the Coolify API:

- Compose files are submitted as base64 `docker_compose_raw` to Coolify.
- Env vars (including `SENTRY_DSN`, DB URLs, service tokens) are pushed as Coolify app env vars — **never** written to `/opt/<project>/.env` on disk.
- Traefik labels are generated by Coolify's compose processor, not by Fabrik.

**Implications for this plan:**

| Thing we do | Who owns it |
|-------------|-------------|
| App compose + env vars | Coolify API |

| Infra services: Backrest, Authelia, Gatus, monitoring stack | Us (direct SSH on `/opt/<svc>/compose.yaml`) — **not** in Coolify |

The old GlitchTip `.env` fallback in Issue #7's previous draft violated this invariant — it wrote `SENTRY_DSN` into `/opt/<project>/.env`. That fallback is **removed**. Coolify API env var is the only path.

### Issue #1: Shell Injection via `ssh` + `tee` Pattern

**Problem:**
```python
# ❌ DANGEROUS - Two layers of shell quoting
config_json_escaped = config_json.replace("'", "'\\''")
ssh(f"echo '{config_json_escaped}' | sudo tee {BACKREST_CONFIG}")
```

**Why it breaks:**
- Single-quote escaping through SSH through shell = quoting hell
- JSON with embedded quotes, newlines, unicode → corruption
- `echo` behavior varies (dash vs bash)
- Already seen this pattern fail with complex YAML

**Validation:**
```python
# Test case that WILL break current implementation:
test_json = {
    "message": "User's \"special\" config\nwith newlines",
    "unicode": "日本語",
    "nested": {"quote": "it's broken"}
}
# Current approach: FAILS with shell parsing errors
```

**✅ FIXED: Base64 encoding (already used in Coolify driver)**

```python
import base64

def write_config_via_ssh(config_content: str, remote_path: str, dry_run: bool = False) -> None:
    """Write config file to VPS via SSH using base64 encoding.

    Safe for any content: JSON, YAML, unicode, quotes, newlines.
    No shell escaping required.

    Args:
        config_content: File content to write
        remote_path: Destination path on VPS
        dry_run: Simulate only
    """
    if dry_run:
        logger.info("[DRY RUN] Would write config to %s", remote_path)
        return

    # Base64 encode (works for any content)
    payload = base64.b64encode(config_content.encode()).decode()

    # Write via base64 decode (no escaping needed)
    ssh(f"echo '{payload}' | base64 -d | sudo tee {remote_path} > /dev/null")

    logger.debug("Wrote config to %s (%d bytes)", remote_path, len(config_content))
```

**Apply to all config writes:**

```python
# Backrest
config_json = json.dumps(config, indent=2)
write_config_via_ssh(config_json, BACKREST_CONFIG, dry_run)

# Authelia
config_yaml = yaml.dump(config, default_flow_style=False, sort_keys=False)
write_config_via_ssh(config_yaml, AUTHELIA_CONFIG, dry_run)

# Gatus (already uses scp, which is safe)
```

**Impact:** Eliminates entire class of shell injection / corruption bugs.

### Issue #2: `fcntl.flock` Only Locks Local Machine, Not VPS

**Problem:**
```python
# ❌ ONLY PREVENTS LOCAL RACES
class SSHLock:
    def __enter__(self):
        fcntl.flock(self.fd, fcntl.LOCK_EX)  # Locks /tmp/fabrik-*.lock on LOCAL machine
```

**Why it breaks:**
- Prevents two `fabrik apply` on **same machine** ✅
- Does NOT prevent `fabrik apply` from **different machines** ❌
- Scenarios:
  - Laptop + CI pipeline both deploying
  - Two n8n workers running simultaneously
  - Developer + automation racing

**Validation:**
```bash
# Terminal 1 (Laptop):
fabrik apply project-a  # Acquires local lock

# Terminal 2 (CI server):
fabrik apply project-a  # Acquires DIFFERENT local lock → RACE CONDITION
```

**✅ FIXED: VPS-side locking with `flock(1)`**

```python
"""VPS-side file locking for distributed deployments."""
import logging
from fabrik.drivers.ssh import ssh

logger = logging.getLogger(__name__)

class VPSLock:
    """VPS-side file lock for multi-machine deployments.

    Uses flock(1) on the VPS to ensure exclusive access across
    all machines running fabrik apply.

    Usage:
        with VPSLock("backrest-config"):
            # Exclusive access to Backrest config across ALL machines
            modify_config()
    """

    [earlier broken context-manager draft removed — see below]
```

**⚠️ Reviewer caught a fatal bug in the previous draft (verified 2026-04-18 11:20):**

The context-manager VPSLock opened an SSH session, ran `flock -x -w 30 … -c 'echo locked'`, and returned. `flock` released the lock the instant `echo locked` exited — *before* `__enter__` returned. Every subsequent `ssh()` inside the `with` block ran in a fresh SSH session with **no lock held**.

Proven on this VPS:

```text
$ ssh vps "flock -x /tmp/tlp.lock -c 'echo FIRST at \$(date +%s)'; \
           flock -x -w 1 /tmp/tlp.lock -c 'echo SECOND at \$(date +%s)'"
FIRST at 1776500626
SECOND at 1776500626   ← same second, lock released between calls
```

Python-side orchestration of SSH calls **cannot** hold a remote file lock. Scrap the context manager.

**✅ CORRECT PATTERN: run the entire mutation as one remote script under flock**

```python
"""VPS-side file locking — single-script pattern.

The lock is held for the entire duration of the bash script on the VPS,
across read → modify → validate → write → restart. The lock cannot leak
between Python-side ssh() calls because there are no between-calls.
"""
import base64
import json
import logging
import shlex

from fabrik.drivers.ssh import ssh

logger = logging.getLogger(__name__)


def run_locked(resource: str, script: str, timeout: int = 120) -> str:
    """Run a bash script on the VPS under an exclusive file lock.

    Args:
        resource: Lock name, e.g. 'backrest-config'. Lock file is
                  /tmp/fabrik-{resource}.lock on the VPS.
        script:   Full bash script. MUST use `set -euo pipefail` and
                  combine all steps with && / ; — lock releases when
                  the script exits.
        timeout:  Seconds to wait for lock acquisition (default 120).

    Returns:
        stdout from the script.

    Raises:
        RuntimeError on lock timeout or script non-zero exit.

    Example:
        script = '''set -euo pipefail
        CFG=/opt/backrest/config/config.json
        sudo cp $CFG $CFG.bak.$(date +%Y%m%d-%H%M%S)
        ... everything in one script ...
        '''
        run_locked('backrest-config', script)
    """
    # shlex.quote is safe for arbitrary script content (quotes, newlines, unicode)
    lock_file = f"/tmp/fabrik-{resource}.lock"
    cmd = f"flock -x -w {timeout} {lock_file} bash -c {shlex.quote(script)}"
    return ssh(cmd)
```

**Backrest `add_backup_plan` rewritten with this pattern:**

```python
def add_backup_plan(
    plan_id: str,
    paths: list[str],
    schedule_cron: str = "0 3 * * *",
    dry_run: bool = False,
) -> dict:
    """Add Backrest backup plan atomically under VPS lock.

    Uses jq for idempotent, typesafe JSON mutation. Lock held for the
    entire read-validate-write-restart cycle. Requires `jq` on the VPS
    (verified available at /usr/bin/jq 2026-04-18).
    """
    if dry_run:
        return {"status": "dry_run", "plan": plan_id}

    # Build the plan object locally, ship as base64 to avoid shell escaping
    new_plan = {
        "id": plan_id,
        "repo": "b2-vps1",
        "paths": paths,
        "excludes": ["**/cache", "**/*.log", "**/tmp"],
        "schedule": {"cron": schedule_cron},
        # hooks omitted for brevity — add Apprise failure notify here
    }
    payload = base64.b64encode(json.dumps(new_plan).encode()).decode()

    script = f"""set -euo pipefail
CFG=/opt/backrest/config/config.json

# Idempotency: skip if plan already exists
if sudo jq -e '.plans[]? | select(.id=={json.dumps(plan_id)})' "$CFG" >/dev/null 2>&1; then
    echo "EXISTS"
    exit 0
fi

# Backup first
BAK="$CFG.bak.$(date +%Y%m%d-%H%M%S)"
sudo cp "$CFG" "$BAK"

# Mutate via jq (atomic: write to .tmp then mv)
NEW_PLAN=$(echo {shlex.quote(payload)} | base64 -d)
sudo jq --argjson p "$NEW_PLAN" '.plans = ((.plans // []) + [$p])' "$CFG" \\
    | sudo tee "$CFG.tmp" >/dev/null

# Validate JSON — restore on corruption
if ! sudo python3 -m json.tool "$CFG.tmp" >/dev/null; then
    sudo rm -f "$CFG.tmp"
    sudo cp "$BAK" "$CFG"
    echo "CORRUPT_RESTORED" >&2
    exit 1
fi

sudo mv "$CFG.tmp" "$CFG"

# Cleanup: keep last 10 backups
sudo bash -c 'ls -t $CFG.bak.* 2>/dev/null | tail -n +11 | xargs -r rm -f' || true

# Restart Backrest so it picks up new config
sudo docker restart $(sudo docker ps --format '{{{{.Names}}}}' | grep '^backrest-')
echo "CREATED"
"""
    out = run_locked("backrest-config", script, timeout=120)
    status = "created" if "CREATED" in out else "exists"
    return {"status": status, "plan": plan_id}
```

Authelia `add_access_rule` follows the same pattern with `yq` (or inline Python) instead of `jq`.

**Impact:** Multi-machine concurrent `fabrik apply` now actually serialized on the VPS. The context-manager `VPSLock` and `SSHLock` from earlier iterations are **deleted** from the plan — they were security theatre.

### Issue #3: DNS Propagation Check Resolves from Wrong Location

**Problem:**
```python
# ❌ CHECKS LOCAL DNS, NOT VPS OR LET'S ENCRYPT
socket.gethostbyname(domain)  # Hits YOUR local resolver
```

**Why it breaks:**
- Your local DNS can be cached-clean
- Traefik/Let's Encrypt resolve from **VPS** and **ACME validation servers**
- Let's Encrypt can still get NXDOMAIN while your check passes
- Result: SSL cert issuance fails even though DNS "propagated"

**Validation:**
```bash
# Your machine (cached):
nslookup test.vps1.ocoron.com
# → Returns 172.93.160.197 ✅

# VPS (fresh):
ssh vps "nslookup test.vps1.ocoron.com"
# → NXDOMAIN ❌

# Let's Encrypt validation fails → no SSL cert
```

**✅ FIXED: Multi-perspective DNS verification**

```python
"""DNS propagation verification from multiple perspectives."""
import logging
import time
from fabrik.drivers.ssh import ssh

logger = logging.getLogger(__name__)

def wait_for_dns_propagation(
    domain: str,
    expected_ip: str = "172.93.160.197",
    max_wait: int = 60,
    check_interval: int = 2,
) -> bool:
    """Wait for DNS A record to propagate from multiple perspectives.

    Checks:
    1. VPS resolver (where Traefik runs)
    2. Public resolver (1.1.1.1 - where Let's Encrypt validates)

    Both must succeed before returning True.

    Args:
        domain: Domain to check (e.g., 'my-project.vps1.ocoron.com')
        expected_ip: Expected IP address (default: VPS IP)
        max_wait: Maximum seconds to wait (default: 60)
        check_interval: Seconds between checks (default: 2)

    Returns:
        True if DNS propagated to all perspectives, False if timeout
    """
    logger.info("Waiting for DNS propagation: %s → %s", domain, expected_ip)
    start = time.time()

    checks = {
        "vps": False,      # VPS resolver (Traefik perspective)
        "public": False,   # Public resolver (Let's Encrypt perspective)
    }

    while time.time() - start < max_wait:
        # Check 1: VPS resolver (where Traefik runs)
        if not checks["vps"]:
            try:
                # getent uses VPS system resolver
                result = ssh(f"getent hosts {domain}").strip()
                if result and expected_ip in result:
                    checks["vps"] = True
                    logger.info("✓ DNS propagated to VPS resolver")
            except RuntimeError:
                pass  # NXDOMAIN or timeout

        # Check 2: Public resolver (where Let's Encrypt validates)
        if not checks["public"]:
            try:
                # dig @1.1.1.1 queries Cloudflare public DNS
                result = ssh(f"dig +short @1.1.1.1 {domain}").strip()
                if result == expected_ip:
                    checks["public"] = True
                    logger.info("✓ DNS propagated to public resolver (1.1.1.1)")
            except RuntimeError:
                pass  # NXDOMAIN or timeout

        # Success: both perspectives see the record
        if all(checks.values()):
            elapsed = time.time() - start
            logger.info("✓ DNS fully propagated for %s (%.1fs)", domain, elapsed)
            return True

        # Wait before next check
        time.sleep(check_interval)

    # Timeout: report which checks failed
    failed = [k for k, v in checks.items() if not v]
    logger.warning(
        "DNS propagation timeout for %s after %ds. Failed checks: %s",
        domain, max_wait, failed
    )
    return False


def verify_dns_before_deployment(domain: str, max_wait: int = 60) -> None:
    """Verify DNS propagation before Coolify deployment.

    Raises RuntimeError if DNS not propagated within timeout.

    Args:
        domain: Domain to verify
        max_wait: Maximum seconds to wait

    Raises:
        RuntimeError: If DNS not propagated
    """
    if not wait_for_dns_propagation(domain, max_wait=max_wait):
        raise RuntimeError(
            f"DNS propagation failed for {domain}. "
            f"Traefik/Let's Encrypt will not be able to route traffic or issue SSL cert. "
            f"Check DNS provider and try again."
        )
```

**Integration:**

```python

# NEW: Wait for multi-perspective propagation
verify_dns_before_deployment(domain, max_wait=60)

```

**Impact:** Eliminates SSL cert failures from premature deployment.

```python
"""Git-based config versioning for non-secret config directories."""
import logging
from fabrik.drivers.ssh import ssh

logger = logging.getLogger(__name__)

GIT_VERSIONED_DIRS = {
    "/opt/monitoring/configs/gatus",  # Endpoint YAMLs — no secrets
}


def git_commit_config(config_dir: str, message: str, dry_run: bool = False) -> None:
    """Commit config changes to Git for audit trail.

    Only versions directories in GIT_VERSIONED_DIRS. Rejects attempts to
    version known-secret-bearing paths (Backrest, Authelia).

    Args:
        config_dir: Directory to version
        message: Commit message
        dry_run: Simulate only

    Raises:
        ValueError: If config_dir is not in the whitelist
    """
    if config_dir not in GIT_VERSIONED_DIRS:
        raise ValueError(
            f"Refusing to git-version {config_dir}: not in GIT_VERSIONED_DIRS whitelist. "
            f"Secret-bearing configs rely on timestamped .bak files instead."
        )

    if dry_run:
        logger.info("[DRY RUN] Would git-commit %s: %s", config_dir, message)
        return

    try:
        ssh(f"cd {config_dir} && (git rev-parse --git-dir >/dev/null 2>&1 || git init -q)")
        ssh(f"cd {config_dir} && git config user.name 'Fabrik Automation'")
        ssh(f"cd {config_dir} && git config user.email 'fabrik@ocoron.com'")
        ssh(f"cd {config_dir} && chmod 700 .git")  # Defense-in-depth
        ssh(f"cd {config_dir} && git add -A && git commit -m '{message}' --allow-empty || true")
        logger.info("Git commit: %s → %s", config_dir, message)
    except Exception as e:
        # Non-fatal — Issue #9 adds metric/alert for accumulating failures
        logger.warning("Git commit failed (non-fatal): %s", e)
        record_git_failure(config_dir, str(e))
```

### Issue #5: Architecture Check Uses Regex Instead of YAML Parser

**Problem:**
```python
# ❌ REGEX MISSES MULTI-SERVICE EDGE CASES
platform_match = re.search(r'platform:\s*(\S+)', compose_yaml)
```

**Why it breaks:**
- Multi-service compose where only ONE service has wrong platform
- Comments containing "platform:"
- YAML anchors and aliases

**Example that breaks:**
```yaml
services:
  app:
    platform: linux/amd64  # ✅ Correct
  worker:
    platform: linux/arm64  # ❌ Wrong, but regex only finds first match
```

**✅ FIXED: Use PyYAML parser**

```python
"""Architecture verification using YAML parser."""
import logging
import yaml
from fabrik.drivers.ssh import ssh
from fabrik.orchestrator.context import DeploymentContext

logger = logging.getLogger(__name__)

def verify_architecture(ctx: DeploymentContext) -> None:
    """Verify VPS architecture matches ALL services in compose spec.

    Args:
        ctx: Deployment context with spec

    Raises:
        RuntimeError: If any service has architecture mismatch
    """
    # Get VPS architecture
    vps_arch = ssh("uname -m").strip()

    arch_map = {
        "x86_64": "amd64",
        "aarch64": "arm64",
        "armv7l": "arm/v7",
        "armv6l": "arm/v6",
    }

    vps_platform = f"linux/{arch_map.get(vps_arch, vps_arch)}"
    logger.info("VPS architecture: %s", vps_platform)

    # Parse compose.yaml with YAML parser
    compose_yaml = ctx.spec.get("compose_yaml", "")
    if not compose_yaml:
        logger.warning("No compose_yaml in spec, skipping architecture check")
        return

    try:
        compose = yaml.safe_load(compose_yaml)
    except yaml.YAMLError as e:
        raise RuntimeError(f"Invalid compose YAML: {e}")

    # Check EVERY service for platform directive
    mismatches = []
    services = compose.get("services", {})

    for svc_name, svc_config in services.items():
        if "platform" in svc_config:
            svc_platform = svc_config["platform"]

            if svc_platform != vps_platform:
                mismatches.append({
                    "service": svc_name,
                    "expected": vps_platform,
                    "actual": svc_platform,
                })

    if mismatches:
        error_msg = f"Architecture mismatch detected in {len(mismatches)} service(s):\n"
        error_msg += f"VPS architecture: {vps_platform}\n\n"

        for m in mismatches:
            error_msg += f"  Service '{m['service']}':\n"
            error_msg += f"    Expected: {m['expected']}\n"
            error_msg += f"    Actual:   {m['actual']}\n"

        error_msg += "\nThis will cause 'Exec Format Error' on deployment.\n"
        error_msg += f"Fix: Update platform directives to '{vps_platform}' in compose.yaml"

        raise RuntimeError(error_msg)

    # Check if ANY service has platform directive
    has_platform = any("platform" in svc for svc in services.values())

    if not has_platform:
        logger.warning(
            "No platform directives found in compose.yaml. "
            "Add 'platform: %s' to all services to prevent architecture issues.",
            vps_platform
        )
    else:
        logger.info("Architecture check passed: all services use %s ✓", vps_platform)
```

**Impact:** Catches architecture mismatches in multi-service composes.

### Issue #6: Traefik 5-Second Sleep is a Guess, Not a Signal

**Problem:**
```python

time.sleep(5)  # Hope Traefik is ready
```

**Why it's suboptimal:**
- Takes 5 seconds even if Traefik is ready in 1 second
- Might not be enough if Traefik is slow
- No confirmation that router actually exists

**✅ FIXED: Poll Traefik API over SSH (localhost-only after security fix)**

**Prerequisite:** Traefik API port 8080 is now bound to `127.0.0.1:8080` on the VPS (see Pre-flight Security Fix at top of doc). Polling happens via SSH → `curl localhost:8080`, never directly from the WSL/CI machine.

```python
"""Traefik router verification via API (SSH → VPS localhost)."""
import json
import logging
import time

from fabrik.drivers.ssh import ssh

logger = logging.getLogger(__name__)


def wait_for_traefik_router(
    project_name: str,
    max_wait: int = 30,
    check_interval: int = 1,
) -> bool:
    """Wait for Traefik to detect new router.

    Polls Traefik API over SSH (port 8080 is bound to VPS localhost only).
    Distinguishes "Traefik down / API unreachable" from "JSON malformed"
    so timeout errors carry a useful cause.

    Args:
        project_name: Router name substring to match (Coolify prefixes with project)
        max_wait: Maximum seconds to wait
        check_interval: Seconds between checks

    Returns:
        True if router detected, False on timeout
    """
    logger.info("Waiting for Traefik router: %s", project_name)
    start = time.time()
    last_err: str | None = None

    while time.time() - start < max_wait:
        try:
            # -s silent, -f fail on HTTP errors, --max-time bounds hang
            result = ssh("curl -sf --max-time 3 http://localhost:8080/api/http/routers")
            routers = json.loads(result)

            if any(project_name in r.get("name", "") for r in routers):
                elapsed = time.time() - start
                logger.info("✓ Traefik router detected for %s (%.1fs)", project_name, elapsed)
                return True
        except json.JSONDecodeError as e:
            last_err = f"invalid JSON from Traefik API: {e}"
        except RuntimeError as e:
            last_err = f"SSH/curl failed: {e}"

        time.sleep(check_interval)

    logger.warning(
        "Traefik router not detected for %s after %ds (last error: %s)",
        project_name, max_wait, last_err,
    )
    return False


def restart_traefik_and_wait(project_name: str, ctx: DeploymentContext) -> None:
    """Restart Traefik and wait for router detection.

    Args:
        project_name: Project name
        ctx: Deployment context

    Raises:
        RuntimeError: If router not detected after restart
    """
    if ctx.dry_run:
        logger.info("[DRY RUN] Would restart Traefik and wait for router")
        return

    logger.info("Restarting Traefik to detect new container...")
    ssh("sudo docker restart traefik")

    # Wait for Traefik to come back up
    time.sleep(2)

    # Poll for router (typically 1-3 seconds)
    if not wait_for_traefik_router(project_name, max_wait=30):
        raise RuntimeError(
            f"Traefik did not detect router for {project_name} after restart. "
            f"Check Traefik logs: docker logs traefik"
        )

    logger.info("Traefik restart complete and router detected ✓")
```

**Impact:** Faster deployments (1-3s instead of fixed 5s) with confirmation.

### Issue #7: GlitchTip Hybrid Approach Has Silent Failure Mode

**Problem:**
```python
# ❌ ASSUMES SUCCESS WITHOUT VERIFICATION

coolify.redeploy(ctx.deployment_id)

```

**Why it breaks:**
- Coolify API returns 200 OK
- Redeploy starts but fails (out of memory, image pull error, etc.)
- Container runs with OLD env vars
- You think DSN is injected but it's not

**✅ FIXED: Post-injection verification**

```python
"""GlitchTip DSN injection with verification."""
import logging
from fabrik.drivers.ssh import ssh
from fabrik.drivers.glitchtip import create_project
from fabrik.drivers.coolify import CoolifyClient

logger = logging.getLogger(__name__)

def verify_dsn_injection(project_name: str, expected_dsn: str, max_wait: int = 60) -> bool:
    """Verify DSN is actually injected in running container.

    Args:
        project_name: Project name
        expected_dsn: Expected DSN value
        max_wait: Maximum seconds to wait for container restart

    Returns:
        True if DSN verified, False otherwise
    """
    import time
    start = time.time()

    while time.time() - start < max_wait:
        try:
            # Find container (Coolify adds UUID suffix)
            container = ssh(
                f"sudo docker ps --format '{{{{.Names}}}}' | grep '^{project_name}-' | head -1"
            ).strip()

            if not container:
                time.sleep(2)
                continue

            # Check env var in running container
            actual_dsn = ssh(f"sudo docker exec {container} printenv SENTRY_DSN 2>/dev/null || echo ''").strip()

            if actual_dsn == expected_dsn:
                logger.info("✓ DSN verified in container: %s", container)
                return True

        except Exception as e:
            logger.debug("DSN verification attempt failed: %s", e)

        time.sleep(2)

    return False


def _provision_glitchtip(
    self,
    name: str,
    ctx: DeploymentContext,
    dry_run: bool
) -> None:
    """Create GlitchTip project and inject DSN with verification."""
    try:
        # Create GlitchTip project
        result = create_project(name, dry_run=dry_run)

        if result["status"] != "created":
            logger.info("GlitchTip: %s → %s", name, result["status"])
            ctx.add_resource("glitchtip", name)
            return

        dsn = result["dsn"]
        logger.info("GlitchTip project created: %s", name)

        # Coolify API is the ONLY supported path (deployment model invariant).
        # The earlier ".env file fallback" is removed — Coolify-deployed apps
        # must not have plaintext .env files on disk.
        coolify = CoolifyClient()
        coolify.update_env_vars(ctx.deployment_id, {"SENTRY_DSN": dsn})
        logger.info("Triggered Coolify redeploy for DSN injection...")

        if not verify_dsn_injection(name, dsn, max_wait=60):
            raise RuntimeError(
                "DSN not found in container after Coolify redeploy. "
                "Check Coolify deployment logs — do NOT fall back to writing .env."
            )
        logger.info("✓ GlitchTip DSN verified in running container")

        ctx.add_resource("glitchtip", name)

    except Exception as e:
        # Rollback: delete the orphaned GlitchTip project so it doesn't
        # accumulate on repeated failures (reviewer: previous round missed this).
        try:
            from fabrik.drivers.glitchtip import delete_project
            delete_project(name)
            logger.warning("Deleted orphaned GlitchTip project after failure: %s", name)
        except Exception as rollback_err:
            logger.error("GlitchTip rollback also failed: %s", rollback_err)
        # Re-raise so the orchestrator sees the failure and runs full rollback
        raise
```

**Deployment-model invariant:** All Fabrik-managed apps deploy via the Coolify API. Env vars, compose files, and build artifacts are pushed to Coolify — never written as plaintext `.env` files on `/opt/<project>/`. The old ".env fallback" in the previous draft violated this invariant and has been removed.

**Impact:** Eliminates silent failures in DSN injection. Eliminates orphan GlitchTip projects on failure. Stays consistent with the Coolify-only deployment model.

```python
def cleanup_old_backups(config_path: str, keep_last: int = 10) -> None:
    """Remove old backup files, keeping only the most recent N.

    Args:
        config_path: Config file path (e.g., '/opt/backrest/config/config.json')
        keep_last: Number of backups to keep (default: 10)
    """
    try:
        # List all backup files sorted by timestamp (newest first)
        backups = ssh(
            f"ls -t {config_path}.bak.* 2>/dev/null || echo ''"
        ).strip().split('\n')

        backups = [b for b in backups if b]  # Remove empty strings

        if len(backups) > keep_last:
            to_delete = backups[keep_last:]
            logger.info("Cleaning up %d old backup(s)", len(to_delete))

            for backup in to_delete:
                ssh(f"sudo rm -f {backup}")

            logger.info("Kept %d most recent backup(s)", keep_last)

    except Exception as e:
        logger.warning("Backup cleanup failed (non-fatal): %s", e)


# Usage in add_backup_plan:
def add_backup_plan(...):

    ssh(f"sudo cp {BACKREST_CONFIG} {backup_path}")
```

### Issue #10: No Rollback Story for Partial Deployments

**Problem:**
```
Step 3: DNS ✅
Step 4: Coolify deploy ✅
Step 5: Backrest write ❌ FAILS
→ What state is the system in?
→ How do we recover?
```

**✅ FIXED: Document recovery path + cleanup handler**

```python
"""Deployment rollback and recovery."""
import logging
from fabrik.orchestrator.context import DeploymentContext

logger = logging.getLogger(__name__)

class DeploymentRollback:
    """Rollback handler for partial deployment failures."""

    def __init__(self, ctx: DeploymentContext):
        self.ctx = ctx
        self.completed_steps = []

    def mark_completed(self, step: str):
        """Mark a step as completed (for rollback)."""
        self.completed_steps.append(step)
        logger.debug("Deployment step completed: %s", step)

    def rollback(self):
        """Rollback completed steps in reverse order."""
        logger.warning("Rolling back %d completed step(s)", len(self.completed_steps))

        for step in reversed(self.completed_steps):
            try:
                if step == "dns":
                    self._rollback_dns()
                elif step == "coolify":
                    self._rollback_coolify()
                elif step == "gatus":
                    self._rollback_gatus()
                elif step == "backrest":
                    self._rollback_backrest()
                elif step == "glitchtip":
                    self._rollback_glitchtip()
                # ... other steps ...

                logger.info("Rolled back: %s", step)
            except Exception as e:
                logger.error("Rollback failed for %s: %s", step, e)

    def _rollback_dns(self):
        """Remove DNS A record."""
        from fabrik.drivers.dns import DNSClient
        domain = self.ctx.spec.get("domain")
        if domain:
            DNSClient.remove_subdomain(domain)

    def _rollback_coolify(self):
        """Delete Coolify application after confirming it's not mid-deploy.

        Previous round bug: called delete_application immediately, which
        can race with an in-flight Coolify deploy and leave orphan state.
        """
        from fabrik.drivers.coolify import CoolifyClient
        if not self.ctx.deployment_id:
            return
        client = CoolifyClient()
        # Grace period: poll deployment status until settled (<=60s), then delete.
        import time
        deadline = time.time() + 60
        while time.time() < deadline:
            status = client.get_deployment_status(self.ctx.deployment_id)
            if status in ("succeeded", "failed", "cancelled", "not_found"):
                break
            time.sleep(3)
        client.delete_application(self.ctx.deployment_id)

    def _rollback_gatus(self):
        """Remove Gatus endpoint."""
        from fabrik.drivers.gatus import remove_endpoint
        name = self.ctx.spec.get("name")
        if name:
            remove_endpoint(name)

    def _rollback_backrest(self):
        """Restore Backrest config from the most recent .bak and restart.

        Fixes the previous-round bug where `cp {path}.bak.* {path} | head -1`
        both mis-used cp (multiple sources → non-directory dest = error) and
        piped cp's empty stdout into head. Must pick the latest .bak first,
        then restore, then restart the container so it re-reads config.
        """
        latest = ssh(
            f"ls -t {BACKREST_CONFIG}.bak.* 2>/dev/null | head -1"
        ).strip()
        if not latest:
            logger.warning("No Backrest backup found to restore from")
            return
        ssh(f"sudo cp {latest} {BACKREST_CONFIG}")
        ssh(
            "sudo docker restart $(sudo docker ps --format '{{.Names}}' "
            "| grep '^backrest-')"
        )
        logger.info("Restored Backrest config from %s and restarted", latest)

    def _rollback_glitchtip(self):
        """Delete orphaned GlitchTip project (previous round missed this)."""
        from fabrik.drivers.glitchtip import delete_project
        name = self.ctx.spec.get("name")
        if name:
            delete_project(name)


# Usage in orchestrator:
def deploy(self, ctx: DeploymentContext):
    rollback = DeploymentRollback(ctx)

    try:
        # Step 3: DNS
        self._provision_dns(ctx)
        rollback.mark_completed("dns")

        # Step 4: Coolify
        self._deploy_to_coolify(ctx)
        rollback.mark_completed("coolify")

        # Step 6: Infrastructure
        self._provision_infrastructure(ctx)
        rollback.mark_completed("gatus")
        rollback.mark_completed("backrest")

    except Exception as e:
        logger.error("Deployment failed: %s", e)
        rollback.rollback()
        raise
```

**Recovery documentation:**

```markdown

**State:** DNS points to VPS, but no container running
**Recovery:**
1. DNS will auto-expire (TTL: 300s)
```
