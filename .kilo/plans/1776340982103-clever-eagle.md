# Plan: Zero-Touch Deployment — Automated Infrastructure Provisioning

**Goal:** `fabrik apply my-project` automatically configures ALL infrastructure services. No manual steps.

**Current:** DNS → Coolify → health check → MANUAL: database, monitoring, backup, search, auth
**Desired:** DNS → Coolify → health check → AUTO: PostgreSQL, Uptime Kuma, MeiliSearch, Authelia

---

## Architecture Overview

```
fabrik apply my-project
  │
  ├─ Step 1: Validate spec                          (existing)
  ├─ Step 2: Load secrets                            (existing)
  ├─ Step 3: DNS provisioning                        (existing)
  ├─ Step 4: Coolify deploy                          (existing)
  ├─ Step 5: Health verification                     (existing)
  │
  ├─ Step 6: Infrastructure provisioning             (NEW)
  │   ├─ 6a: PostgreSQL — CREATE DATABASE via SSH    (if provisioning.database)
  │   ├─ 6b: Uptime Kuma — add HTTP monitor          (if domain exists)
  │   ├─ 6c: MeiliSearch — create index via driver   (if provisioning.meilisearch)
  │   └─ 6d: Authelia — SSH edit YAML + restart      (if provisioning.authelia)
  │
  └─ Step 7: Complete                                (existing)
```

### Key Technical Constraints Discovered

1. **`infrastructure` field name is taken.** The `Spec` Pydantic model (`spec_loader.py:157-163, 204`) already has `infrastructure: Infrastructure` with `DatabaseType`/`StorageType`/`AuthType` enums for backend selection (local vs Supabase vs R2). Our boolean flags must use a different name: **`provisioning`**.

2. **Orchestrator uses raw dicts, not Spec objects.** `SpecValidator.load_and_validate()` returns a plain dict from `yaml.safe_load()`. The `Spec` Pydantic model is only used by `TemplateRenderer` in `deployer.py:156`. So we can add `provisioning` keys to spec YAML without modifying the Pydantic model — the orchestrator reads raw dicts and the `Spec` model has no `model_config = {"extra": "forbid"}` (defaults to "ignore").

3. **State machine gap.** The state machine (`states.py`) allows `VERIFYING → COMPLETE` but has no `PROVISIONING_INFRA` state. Since infrastructure provisioning is **non-fatal best-effort** (the app is already deployed and healthy), we run it between VERIFYING and COMPLETE without a new state. No state machine changes needed.

4. **Two `fabrik apply` code paths.** The CLI has: (a) orchestrator path (`--orchestrator`/`--dry-run`) using `DeploymentOrchestrator.deploy()`, and (b) direct path (default) using `load_spec()` → direct function calls. Infrastructure provisioning goes into the orchestrator path. The direct path should call infrastructure provisioner separately.

5. **`fabrik deploy` also routes to the orchestrator** for non-WordPress projects via `deploy_router.py`. Infrastructure provisioning will work for both `fabrik apply` and `fabrik deploy` paths.

| Decision | Choice | Rationale |
|----------|--------|-----------|

| Grafana | Skip | cAdvisor auto-discovers, existing dashboards suffice |
| n8n | Skip | Workflows are project-specific, generic template has no value |

### Phase 1: SSH Helper Module

**New file:** `src/fabrik/drivers/ssh.py`

Thin wrapper around subprocess SSH to the VPS. Used by PostgreSQL and Authelia provisioning.

```python
"""SSH helper for VPS operations."""
import logging
import subprocess

logger = logging.getLogger(__name__)

def ssh(cmd: str, timeout: int = 60, dry_run: bool = False) -> str:
    """Execute command on VPS via SSH.

    Uses the 'vps' alias from ~/.ssh/config.

    Args:
        cmd: Shell command to run on VPS
        timeout: Timeout in seconds
        dry_run: If True, log but don't execute

    Returns:
        stdout output stripped

    Raises:
        RuntimeError: If SSH command fails
    """
    if dry_run:
        logger.info("[DRY RUN] SSH: %s", cmd)
        return ""

    result = subprocess.run(
        ["ssh", "vps", cmd],
        capture_output=True,
        text=True,
        timeout=timeout,
    )
    if result.returncode != 0:
        raise RuntimeError(f"SSH failed (rc={result.returncode}): {result.stderr.strip()}")
    return result.stdout.strip()
```

**Lines of code:** ~30
**Dependencies:** None (stdlib only)

### Phase 2: PostgreSQL Provisioning

**New file:** `src/fabrik/drivers/postgres.py`

Creates database + user on shared `postgres-main` container via SSH.

```python
"""PostgreSQL database provisioning via SSH to VPS."""
import logging
from fabrik.drivers.ssh import ssh

logger = logging.getLogger(__name__)

def create_database(db_name: str, db_user: str | None = None, dry_run: bool = False) -> dict:
    """Create PostgreSQL database (and optional user) on postgres-main.

    Idempotent — skips if database already exists.

    Args:
        db_name: Database name (e.g., 'my_project')
        db_user: Optional dedicated user (defaults to 'postgres' superuser)
        dry_run: Simulate only

    Returns:
        {"status": "created"|"exists", "database": db_name}
    """
    # Check if database exists
    check = ssh(
        f"docker exec postgres-main psql -U postgres -tAc "
        f"\"SELECT 1 FROM pg_database WHERE datname='{db_name}'\"",
        dry_run=dry_run,
    )
    if check.strip() == "1" or dry_run:
        return {"status": "exists" if not dry_run else "dry_run", "database": db_name}

    # Create database
    ssh(f"docker exec postgres-main psql -U postgres -c 'CREATE DATABASE \"{db_name}\";'")
    logger.info("Created PostgreSQL database: %s", db_name)

    # Create dedicated user if requested
    if db_user and db_user != "postgres":
        ssh(
            f"docker exec postgres-main psql -U postgres -c "
            f"\"DO $$ BEGIN IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname='{db_user}') "
            f"THEN CREATE ROLE \\\"{db_user}\\\" LOGIN; END IF; END $$;\""
        )
        ssh(
            f"docker exec postgres-main psql -U postgres -c "
            f"'GRANT ALL PRIVILEGES ON DATABASE \"{db_name}\" TO \"{db_user}\";'"
        )
        logger.info("Created PostgreSQL user: %s", db_user)

    return {"status": "created", "database": db_name, "user": db_user}
```

**Lines of code:** ~50
**Idempotent:** Yes — checks `pg_database` before CREATE

### Phase 3: MeiliSearch Driver

**New file:** `src/fabrik/drivers/meilisearch.py`

REST API client for MeiliSearch index management.

```python
"""MeiliSearch driver for Fabrik."""
import logging
import os
import httpx

logger = logging.getLogger(__name__)

class MeiliSearchClient:
    """Client for MeiliSearch REST API."""

    def __init__(self, url: str | None = None, api_key: str | None = None):
        self.url = url or os.getenv("MEILISEARCH_URL", "http://search.vps1.ocoron.com")
        self.api_key = api_key or os.getenv("MEILISEARCH_API_KEY", "")
        self._client = httpx.Client(
            base_url=self.url,
            headers={"Authorization": f"Bearer {self.api_key}"} if self.api_key else {},
            timeout=30,
        )

    def health(self) -> dict:
        """Check MeiliSearch health."""
        return self._client.get("/health").json()

    def list_indexes(self) -> list[dict]:
        """List all indexes."""
        resp = self._client.get("/indexes")
        resp.raise_for_status()
        return resp.json().get("results", [])

    def get_index(self, uid: str) -> dict | None:
        """Get index by UID. Returns None if not found."""
        resp = self._client.get(f"/indexes/{uid}")
        if resp.status_code == 404:
            return None
        resp.raise_for_status()
        return resp.json()

    def create_index(self, uid: str, primary_key: str = "id") -> dict:
        """Create index. Idempotent — returns existing if already exists."""
        existing = self.get_index(uid)
        if existing:
            return {"status": "exists", "index": existing}

        resp = self._client.post("/indexes", json={"uid": uid, "primaryKey": primary_key})
        resp.raise_for_status()
        return {"status": "created", "task": resp.json()}

    def delete_index(self, uid: str) -> bool:
        """Delete index by UID."""
        resp = self._client.delete(f"/indexes/{uid}")
        return resp.status_code in (200, 202, 204)

    def close(self):
        self._client.close()

    def __enter__(self):
        return self

    def __exit__(self, *args):
        self.close()
```

**Lines of code:** ~60
**Idempotent:** Yes — checks existing index before CREATE

**Network note:** MeiliSearch is accessible at:
- External: `https://search.vps1.ocoron.com` (through Traefik, protected by `X-Internal-Token` header — layer 3 security)
- Internal: `http://meilisearch:7700` (within Docker network, no auth needed)

The driver uses the external URL from WSL and should pass `SERVICE_INTERNAL_SECRET_KEY` as `X-Internal-Token` header when accessing through Traefik. Update the client to include this:

```python
# In __init__:
self.internal_token = os.getenv("SERVICE_INTERNAL_SECRET_KEY", "")
headers = {}
if self.api_key:
    headers["Authorization"] = f"Bearer {self.api_key}"
if self.internal_token:
    headers["X-Internal-Token"] = self.internal_token
```

Alternatively, the provisioner can SSH into VPS and call MeiliSearch internally (`http://meilisearch:7700`) to avoid token issues. Given that SSH is already available, this is simpler:

```python
# In InfrastructureProvisioner._provision_meilisearch():
# Option A: Use driver with token (WSL → Traefik → MeiliSearch)
# Option B: SSH + curl (WSL → SSH → VPS Docker network → MeiliSearch)
ssh(f"curl -s -X POST 'http://meilisearch:7700/indexes' "
    f"-H 'Authorization: Bearer $MEILI_MASTER_KEY' "
    f"-H 'Content-Type: application/json' "
    f"-d '{{\"uid\": \"{index_uid}\", \"primaryKey\": \"id\"}}'")
```

**Recommendation:** Build the full driver (Option A) for reusability, but support both access patterns. The driver should detect whether it's running on VPS (internal URL) or WSL (external URL + token).

### Phase 4: Authelia Provisioning

**New file:** `src/fabrik/drivers/authelia.py`

Adds access control rules to Authelia config and restarts the container.

**Strategy:** Read YAML on VPS via SSH (`cat`), parse it locally in Python with `yaml.safe_load()`, modify the dict, write it back via SSH (`tee`). This is safer than `sed` on YAML.

```python
"""Authelia access control provisioning via SSH."""
import logging
import yaml as yaml_lib
from fabrik.drivers.ssh import ssh

logger = logging.getLogger(__name__)

AUTHELIA_CONFIG = "/opt/authelia/config/configuration.yml"
AUTHELIA_COMPOSE = "/opt/authelia/compose.yaml"

def add_access_rule(domain: str, policy: str = "two_factor", dry_run: bool = False) -> dict:
    """Add Authelia access control rule for a domain.

    Idempotent — skips if rule for domain already exists.

    Strategy: Read YAML via SSH, parse locally, modify, write back.
    Safer than sed-based YAML manipulation.

    Args:
        domain: Full domain (e.g., 'admin.vps1.ocoron.com')
        policy: 'two_factor' (default), 'one_factor', or 'bypass'
        dry_run: Simulate only

    Returns:
        {"status": "created"|"exists"|"dry_run", "domain": domain}
    """
    if dry_run:
        logger.info("[DRY RUN] Would add Authelia %s rule for %s", policy, domain)
        return {"status": "dry_run", "domain": domain}

    # Read current config via SSH
    config_raw = ssh(f"cat {AUTHELIA_CONFIG}")

    # Parse YAML locally (Python is on WSL, not needed on VPS)
    config = yaml_lib.safe_load(config_raw)

    # Check if rule already exists
    rules = config.get("access_control", {}).get("rules", [])
    for rule in rules:
        if rule.get("domain") == domain:
            logger.info("Authelia rule already exists for %s", domain)
            return {"status": "exists", "domain": domain}

    # Add new rule BEFORE the catch-all (last rule)
    new_rule = {"domain": domain, "policy": policy}
    if len(rules) > 0:
        rules.insert(-1, new_rule)  # Before catch-all deny
    else:
        rules.append(new_rule)

    # Write back via SSH
    config_out = yaml_lib.dump(config, default_flow_style=False, sort_keys=False)
    # Use heredoc to avoid shell escaping issues
    ssh(f"cat << 'AUTHELIA_EOF' | sudo tee {AUTHELIA_CONFIG} > /dev/null\n{config_out}\nAUTHELIA_EOF")

    # Validate config before restart
    try:
        ssh(f"sudo docker compose -f {AUTHELIA_COMPOSE} exec -T authelia authelia validate-configuration")
    except RuntimeError as e:
        logger.error("Authelia config validation failed — rolling back: %s", e)
        # Restore original config
        ssh(f"cat << 'AUTHELIA_EOF' | sudo tee {AUTHELIA_CONFIG} > /dev/null\n{config_raw}\nAUTHELIA_EOF")
        raise

    # Restart Authelia to pick up config change
    ssh(f"sudo docker compose -f {AUTHELIA_COMPOSE} restart authelia")
    logger.info("Added Authelia %s rule for %s and restarted", policy, domain)

    return {"status": "created", "domain": domain, "policy": policy}
```

**Lines of code:** ~65
**Idempotent:** Yes — checks existing rules by domain match
**Safety:** Parses YAML properly in Python (locally), validates config before restart, restores original on validation failure. No fragile `sed` on YAML.

### Phase 5: Infrastructure Provisioner (Orchestrator Integration)

**New file:** `src/fabrik/orchestrator/infrastructure.py`

Central coordinator that reads `provisioning` flags from spec/project.yaml and calls the appropriate provisioners.

```python
"""Infrastructure provisioning — post-deploy service configuration."""
import logging

from fabrik.orchestrator.context import DeploymentContext

logger = logging.getLogger(__name__)

class InfrastructureProvisioner:
    """Provision infrastructure services based on spec provisioning flags.

    NOTE: Uses 'provisioning' key in spec, NOT 'infrastructure' (which is
    taken by the Spec Pydantic model for backend type selection).
    """

    def provision(self, ctx: DeploymentContext) -> None:
        """Run all applicable infrastructure provisioning steps.

        Called after Coolify deploy + health verification.
        Each step is idempotent and non-fatal (warnings, not errors).

        Reads flags from spec["provisioning"] dict:
          - database: bool — create PostgreSQL database on postgres-main
          - meilisearch: bool — create MeiliSearch index
          - authelia: bool — add 2FA access control rule
        Uptime Kuma is always provisioned if domain exists.
        """
        spec = ctx.spec
        prov = spec.get("provisioning", {})
        domain = spec.get("domain")
        name = spec.get("name", spec.get("id", "unknown"))
        dry_run = ctx.dry_run

        # 6a: PostgreSQL database
        if prov.get("database", False):
            self._provision_postgres(name, ctx, dry_run)

        # 6b: Uptime Kuma monitoring (always if domain exists)
        if domain:
            self._provision_monitoring(name, domain, spec, ctx, dry_run)

        # 6c: MeiliSearch index
        if prov.get("meilisearch", False):
            self._provision_meilisearch(name, ctx, dry_run)

        # 6d: Authelia access control
        if prov.get("authelia", False) and domain:
            self._provision_authelia(domain, ctx, dry_run)

    def _provision_postgres(self, name: str, ctx: DeploymentContext, dry_run: bool) -> None:
        """Create PostgreSQL database on postgres-main."""
        try:
            from fabrik.drivers.postgres import create_database

            db_name = name.replace("-", "_")
            result = create_database(db_name, dry_run=dry_run)
            ctx.add_resource("postgres", db_name)
            logger.info("PostgreSQL: %s → %s", db_name, result["status"])
        except Exception as e:
            logger.warning("PostgreSQL provisioning failed (non-fatal): %s", e)

    def _provision_monitoring(
        self, name: str, domain: str, spec: dict, ctx: DeploymentContext, dry_run: bool
    ) -> None:
        """Add Uptime Kuma HTTP monitor."""
        try:
            from fabrik.drivers.uptime_kuma import UptimeKumaClient

            health_path = spec.get("health", {}).get("path", "/health")
            monitor_url = f"https://{domain}{health_path}"
            monitor_name = f"{name} — HTTP"

            if dry_run:
                logger.info("[DRY RUN] Would add Uptime Kuma monitor: %s → %s", monitor_name, monitor_url)
                return

            client = UptimeKumaClient()
            try:
                result = client.add_http_monitor(name=monitor_name, url=monitor_url)
                ctx.add_resource("monitor", monitor_name)
                logger.info("Uptime Kuma: %s → %s", monitor_name, result["status"])
            finally:
                client.disconnect()
        except Exception as e:
            logger.warning("Uptime Kuma provisioning failed (non-fatal): %s", e)

    def _provision_meilisearch(self, name: str, ctx: DeploymentContext, dry_run: bool) -> None:
        """Create MeiliSearch index."""
        try:
            from fabrik.drivers.meilisearch import MeiliSearchClient

            index_uid = name.replace("-", "_")

            if dry_run:
                logger.info("[DRY RUN] Would create MeiliSearch index: %s", index_uid)
                return

            with MeiliSearchClient() as client:
                result = client.create_index(index_uid)
                ctx.add_resource("meilisearch", index_uid)
                logger.info("MeiliSearch: %s → %s", index_uid, result["status"])
        except Exception as e:
            logger.warning("MeiliSearch provisioning failed (non-fatal): %s", e)

    def _provision_authelia(self, domain: str, ctx: DeploymentContext, dry_run: bool) -> None:
        """Add Authelia access control rule."""
        try:
            from fabrik.drivers.authelia import add_access_rule

            result = add_access_rule(domain, dry_run=dry_run)
            ctx.add_resource("authelia", domain)
            logger.info("Authelia: %s → %s", domain, result["status"])
        except Exception as e:
            logger.warning("Authelia provisioning failed (non-fatal): %s", e)
```

**Lines of code:** ~100
**Key design:** Each infrastructure step is **non-fatal** — failures log warnings but don't abort the deployment. The app is already deployed and healthy at this point. Infrastructure provisioning is best-effort enhancement.

## Rollback Considerations

Infrastructure resources are tracked in `DeploymentContext.created_resources`. The existing `RollbackManager` can be extended to handle new resource types:

| Resource Type | Rollback Action |
|---------------|----------------|
| `postgres` | `DROP DATABASE` via SSH |
| `monitor` | `UptimeKumaClient.delete_monitor()` |
| `meilisearch` | `MeiliSearchClient.delete_index()` |
| `authelia` | Remove rule from YAML + restart |

**Phase for rollback:** Deferred — not in initial implementation. Infrastructure provisioning is after health check, so the app is confirmed working. Rollback of infra resources is rare and can be manual initially.
