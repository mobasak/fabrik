# The review loop as a workflow — `fabrik-review-loop`

> **⚠️ NO `Workflow` IN THE HUB — D-961 (operator, 2026-10-18; supersedes D-957 in part).** In the hub — a session whose `git rev-parse --show-toplevel` is `/opt/fabrik` or a worktree under `/opt/fabrik/.claude/worktrees/` — never call the `Workflow` tool. Every `Workflow` launch this page describes (a round-1 pass, a delta or closing pass, a relaunch, a wave) is replaced by its Agent-tool fallback: the same seats and the same briefs as ONE `Agent` message, with each seat's absolute scratch folder and the pass's pin, and the close or the Pass row records `shape: agent-tool`. A workflow, permission or approval question never goes to the operator. Outside the hub this page stands as written.

**What:** the D-335 review loop (`/fabrik-review`, `/fabrik-repo-review` by file; `/fabrik-spec-review`, `/fabrik-plan-review` by section, chunk 6; `/fabrik-review-scoped` and every review-shaped units fan-out, one slice per unit, chunk 6b) run as a Claude Code workflow script,
`.claude/workflows/fabrik-review-loop.js`, so the seat dispatch, the seats' reports and the execution of every
candidate's check happen outside the lead session's transcript — one fresh refuter per slice executes them. One `Workflow` call per pass, one ledger back.
Built as chunk 5 of `docs/reference/command-loop-performance.md` § 5.2 (D-346, D-347, D-348). The shape is
D-335 / D-344 unchanged; only where it runs moved. Row 5b (D-355) replaced one verify seat per candidate with one
refuter per slice: every candidate is still executed (D-330's "every claim executed" holds — save a check the
never-execute rule forbids, which comes back `unverified` with its cited lines for the lead), the seat per candidate
mostly ran one grep (§ 4.9 findings 27, 41), and the refuter's box grows with its candidates (3 minutes each, never
below `box_minutes`). The reviewer agent carries `experimental.cacheTtl: 1h`, which Claude Code ignores while a
subscription is spending usage credits (finding 41).

## Launch (outside the hub — D-961; the command source does this; the lead never dispatches seats one by one)

```text
Workflow({ scriptPath: "<repo root>/.claude/workflows/fabrik-review-loop.js", args: { … } })
```

`<repo root>` is the session's own checkout — `git rev-parse --show-toplevel` from its working directory, so in a worktree the worktree, never the main checkout. The script and its pass reader `scripts/review_loop_ledger.py` are synced to every project (`scripts/fabrik_synced_manifest.py`), so the path exists in any checkout the sync has reached; elsewhere the § Fallback below applies.

| `pass` | 1 on the partitioned round; 2, 3, … on the passes over the slice ledgers, unbounded (the review closes on the pass that confirms zero, whatever its number) |

writes `change.diff`, one `git diff --no-index` per pinned file from a basis to the pin — `--base` when given, else HEAD for a working-tree pin, else `<ref>^` (one commit: a multi-commit range needs `--base`; refuses an absent file, a directory, a symlink, a path outside the repo, a newline in a path, a root file named like a manifest or `change.diff`, and a used dir (`--replace` re-pins one on purpose); and prints the `pins_dir` / `pin_manifest` / `digest` / `base_pin_dir` args fragment (with `pins_digest`, the md5 of `MANIFEST.pins.md5`, which the pass-ledger row records beside `digest`) — pass its `digest` as the launch's `digest`. `pin` is the only way to build the pins a launch accepts: a project whose copy lacks the verb runs the hub's `/opt/fabrik/scripts/review_loop_ledger.py pin` with the same arguments from its own repo root (the root is the working directory); a file `pin` refuses is not a slice file (the refusal names why — `pin --from` accepts a file the working tree has deleted, so a deletion is not always a refusal): review it through its callers in the slice, or run the § Fallback. The CHECKS are two and complementary, so run both before adjudicating: `read --pins <pins_dir>` re-hashes the PINS (a seat mutated one) and, for working-tree pins only, the live files; the PIN rule's live-file check is `md5sum -c --quiet <pins_dir>/MANIFEST.md5` run FROM THE REPO ROOT — it checks the LIVE files only; the COPIES are checked from any cwd by `md5sum -c --quiet <pins_dir>/MANIFEST.pins.md5` (W-1008046c) — which `read --pins` skips for `--from` pins. A FAILED line there means the live file is not the bytes that were pinned — for working-tree pins a write since the pin; for `--from` pins any difference from that commit, the working tree's own WIP or a later commit included — so it is informational like `LIVE MOVED`, never a stop: re-verify that file's candidates against the current tree before you fix or refute them |
| `pin_manifest` | required — the `{ path: md5 }` map `pin` printed, with each slice file named exactly as `pin` printed it. An absent or null manifest, or a slice file it lacks, stops the script before a seat runs, and the error names the `pin` command |
| `base_pin_dir` | optional — the read-only base tree `pin --base` wrote; the seats' recipe copies it (`cp -r`, then `chmod -R u+w` as its own command — the copy keeps the read-only bits, and an overlay that fails leaves the seat on the base bytes) in place of `git archive`; the copy is the WHOLE directory and never `-L` (kaizen 01M5BMDT08: a part dangles a tracked relative link, and a followed link freezes the base bytes so a pinned target never reaches the link path), and the overlay program unlinks a link the change turned into a file rather than writing through it; so a seat runs no `git archive` against the live repo (only a read-only `git ls-tree` when a tracked path is missing from the copy, to see the link `pin --base` skipped). Neither copy carries history: a seat whose test reads git history runs it in a shared clone of the live checkout, made with `git -C SCRATCH clone --shared --no-checkout`, its push URL disabled as a tripwire (its origin is the live repo), never pushing to any remote, path or URL, checked out at the base SHA with the pins overlaid and committed — the recipe is PYTEST_PINS in the script; state a test creates stays in the clone, so only a test reading the live checkout's own refs is unverifiable. `pin --base` records `base_copy` (the commit the copy holds) and `base_skipped` (the members its safe extract left out) in `MANIFEST.json`, and a `--replace` re-pin without `--base` removes the previous pin's `<pins_dir>.base`, which no manifest would then vouch for (W-b976638f). **One command stages a seat's tree:** `python3 -P -B /opt/fabrik/scripts/review_loop_ledger.py stage --pins-dir <pins_dir> --out SCRATCH/arch` (`STAGE_VERB`, prepended to `PIN_IMPORT`) copies the recorded base copy (any other `.base` is ignored) or archives the whole `base_sha` (its tar under `SCRATCH/tmp`, unsafe members SKIPPED as `pin --base` skips them), makes it writable, lays every pin over it by the recipe's link rules — a link at the path replaced, an in-tree parent link written through — checks each overlaid md5, makes `SCRATCH/home` and `SCRATCH/tmp`, and prints one JSON line whose `pytest` value is PYTEST_PINS's launcher with SCRATCH and the repo's `.venv` python filled in (the running python when the repo has no `.venv`), and whose `skipped` names the members the tree leaves out on either route (seats name them UNPINNED). It refuses (exit 2, removing only a tree it created itself) a relative, existing, non-`arch`, quoted or spaced `--out`, a missing scratch dir, an `--out` inside the pins dir, under home or inside a work tree unless ignored (each judged on the path with `..` and symlinked parents resolved), a `home` or `tmp` beside it that is not a directory, a manifest that is missing, empty, unsafe or disagrees with `MANIFEST.md5`, a moved pin, and a pin with neither a recorded copy nor a `base_sha`; deletions in the change are not applied (as in the recipe). The recipe's manual steps stay whole as its fallback (a refusal, or an older copy with no `stage`) |
| `brief` | the dispatcher's shared text: the 16 failure classes, the D8 lessons, the house rules, the referents |
| `slices` | `[{ name, files: [repo-relative…], priority, scope?, models?, agent?, ledger?: [{ id, file, line, claim } \| "<claim>"] }]` — `models` is one to three distinct of `opus`/`sonnet`/`haiku` (default `["sonnet", "haiku"]`, D-344's file-slice pair; a section slice names one seat — `["opus"]` on the rule/grammar sections, `["sonnet"]` on the rest, D-212/D-218; `/fabrik-execute-plan` adds its per-round Opus finder as the riskiest slice's third); `agent` is `fabrik-reviewer` (default) or `fabrik-researcher` for a cited-fact slice, and seats that slice's refuter too; `scope` names the sections of `files` the slice owns; an unknown model or agent, or a repeated or fourth finder, stops the script before a seat runs. `ledger` on pass ≥ 2 (a string row gets the id `<slice>-L<n>`; any other row shape stops the script before a seat runs); each `claim` states the DEFECT as raised — `DEFECT_PRESENT` the defect persists · `DEFECT_ABSENT` it is absent (the fix holds, or an earlier refutation still holds, re-run and never cited) · `NEW` a defect the fix introduced. Every claim in a seat's ledger is re-executed, an earlier refutation included — the closing pass of a quiet round 1 re-executes round 1's claims (term-coverage.md; the Opus + Fable panel, 01M4PPW8D8). A row may carry `recorded: true`: the seat reports it as REPORT ONLY, and a candidate on it moves to the slice's `recorded` list, never reaching the refuter or the counts (D-230), so `candidates` stays index-aligned with `verdicts` |
| `box_minutes` | the seats' hard time box (default 15) |

The tool returns `async_launched`; the ledger arrives as one result — the lead waits for it with ONE bounded in-turn poll per pass, and when the result is truncated reads the run's `journal.jsonl` (one `result` row per completed agent), never the escaped task-output copy. **Each pass is its own invocation** — never
`resumeFromRunId`: a resumed run re-runs every agent after the first fan-out (anthropics/claude-code #63102,
#67488, #74599, #95076 at 2.1.27x). The harness keeps every run's `args` and `result` whole in
`<config dir>/projects/<project>/<session>/workflows/<runId>.json`; the lead copies that file into its scratch and
builds the next pass from the copy (`next --args`) — no seat is ever pointed at the config dir.

## What comes back

```text
{ pass, closable, pinned, dropped_slices, dropped_seats, failed_refuters,
  slices: [{ name, files, seats: [{ model, files_read, raised, confirmed, failed, ledger_status, notes }],
             gaps, raised, distinct, overlap, estimate_unseen, candidates: [..], recorded: [..], verdicts: [..],
             refuter: { retried, failed, unanswered, reason }, closable, open: [..] }] }
```

- `pinned` — always `true`: a launch without `pin_manifest` is refused before it runs; kept so a reader of the field never breaks.
- `seats[].files_read` — a COUNT here (the number of files the seat listed), not the list it returned; the list is in the seat's own result row (`journal.jsonl`). `review_loop_ledger.py read` writes it into the PASS file's `seats[].files_read` as a LIST (every result's non-blank string entries, trimmed and deduplicated), beside the seat's `notes`, so the same key is a count in this ledger and a list in the pass file.
- `candidates` — the two finders' union: two DIFFERENT seats citing the same file and class within five lines are one candidate — a candidate's `file` is normalised as it is taken in, before that comparison, exactly as a `files_read` entry is before its lead test — trimmed, backticks dropped, a leading `file://` or `./` dropped, and one `<pins_dir>/` or `<scratch_dir>/<seat>/arch/` root stripped — so `<pins_dir>/f` and `<scratch_dir>/<seat>/arch/f` name `f` (W-177082fc); a live-checkout or `base_pin_dir` path stays as cited, a value that strips to nothing keeps its original, and no `:line` or annotation suffix is removed (`also` carries the twin's id, `also_seat` its seat, and `also_seats` every seat that raised it — the list the per-seat `confirmed` credit is computed from); the same seat's neighbours are never merged. A candidate both raised credits both seats' `confirmed`.
- `verdicts` — one per candidate from the slice's Sonnet refuter (`effort: high`; the finders run at `medium`): `confirmed | refuted | recorded | unverified`; a check the never-execute rule forbids (a script that deletes, deploys, provisions, writes outside the seat's scratch or contacts a non-local host, by any route — an import, `runpy`, a test, a wrapper) is never run: the refuter returns it `unverified` with the cited lines, and on a later pass the seat leaves that claim out of `ledger_status`, so it stays open for the lead (`SEAT_ISOLATION`, kaizen 01M4W2D1N8); the script writes `unverified` for a candidate the refuter never answered and for a `refuted` with no command or output (refutation needs counter-evidence); a `refuted` whose command is a placeholder (`n/a`, `none`, `-`) or whose output is empty counts as none, and two rows for one id that disagree are `unverified`; the `id` is always the candidate's — the union suffixes a reused id (`#2`) before the refuter sees it — never the seat's echo; a row matches its candidate by exact id, else by a case- or space-folded id that names exactly ONE candidate (the same one-to-one rule `open` applies to ledger ids); with
  the command it ran, the output (≤ 1500 chars), the mechanism, a destination when recorded.
- `gaps` — slice files no finder listed in `files_read`; logged, and the slice is UNVERIFIED until read — on every pass, so a later-pass seat is told to open its whole slice too. An entry
  counts for a slice file `f` when, after stripping one `<pins_dir>/` or `<scratch_dir>/<seat>/arch/` prefix (and
  backticks, `file://`, `./`), it is `f` or begins with `f` followed by whitespace, `:`, `#`, `(`, `[`, `,` or `—` —
  so `f:120`, `f#L120` and `f (pinned copy at …)` count. A trailing slash on either dir is ignored, and an unset or
  empty dir strips nothing. A path under any other root (the live checkout) or a sibling of the same
  name never does (`readsFile` in the script).
- `failed` / `dropped_seats` — a finder that returns null or throws is re-seated ONCE on the same model and agent, labelled `find:<slice>:<model>:retry` with its own scratch dir `seat-…-<slice>-<model>-retry/`, after the first ends (inside the stamp, like the refuter retry); the log line `find:<slice>:<model> null — retried: recovered|STILL NULL` says which (W-b36e2a4a), as `STILL NULL: <the first line of the error>` when the seat REJECTED rather than resolved null, a text the failed seat's `notes` carry too — a seat that died on a terminal API error, a disabled subscription among them, resolves null with no text, so its cause is in its transcript only. **When NO finder of the pass returned anything**, counted over every finder launched as it settles (a slice whose seats returned and whose later stage threw still counts them), the launch THROWS instead of returning a ledger: the message names the finder and slice counts, up to three distinct seat errors (`(+N more)` past three), the known causes — the account lost subscription access, a spent quota, a killed session, a script error — and the check before a relaunch (one seat transcript under the run's `subagents/workflows/<runId>/` folder, and `python3 /opt/fabrik/scripts/sysadmin/claude_rotate.py --status`); the Workflow tool result and the run file's `error` carry it, and `review_loop_ledger.py read` prints its first line after `failed — no result`. Of 2416 completed runs on the box, 5 were all-null, 2 of them on a disabled subscription (2026-10-29). A finder seat is failed when it returns nothing after that retry, when its `files_read` names none of the slice's files, or when it brought nothing back: notes with no coverage statement (the notes up to their first `MACHINERY:` line — the MACHINERY block is the report's last part — empty, a placeholder, or the word placeholder, tbd or todo), no candidate and no ledger row (01M4Q4D8VP; 2 of 6707 real seats, 2026-10-13). For the read-nothing case: it reviewed nothing, and its partner's reads would otherwise hide it from the gap check (01M4C00TSS — a seat answered a relayed operator turn instead). A failed seat's `ledger_status` re-verifies no claim; `dropped_seats` counts them; `review_loop_ledger.py read` flags only the narrower case, a returned finder whose `files_read` names no file at all (`READ 0 FILES`): it has no slice list, so a seat that listed only an off-slice file is failed here and not flagged there — the workflow ledger's `seats[].failed` and `open` are the authority.
- `refuter` / `failed_refuters` — candidates the refuter left unanswered (a null result, a non-array `verdicts`, ids that match none — a deliberate `unverified` row IS an answer) get ONE retry over just those, labelled `refute:<slice>:retry` with its own scratch dir `seat-…-refute-<slice>-retry/` (a dead seat's leftover `arch/` never poisons it); what the retry still leaves unanswered sets `refuter.failed`, adds `refuter failed` to `open` and counts in `failed_refuters` (fleet 01M4DP81PE). `dropped_seats` stays the failed-FINDER count. The workflow's `verdicts` are the authority: `review_loop_ledger.py read` lists both refuters' raw rows, each tagged with its seat. A retry starts only after its first refuter ends, so it never exceeds the stamp's one refuter per slice; the pass log names each retry and whether it recovered, for `round --seats`. Every slice carries `refuter`, `{ retried: false, failed: false, unanswered: 0, reason: '' }` when nothing was lost.
- `closable` / `open` — a slice may close only with no gap, no failed seat, no failed refuter, no `confirmed` or `unverified` verdict and, on a later pass, every ledger claim reported by a seat with a command and a stated output, which may be empty (a grep that finds no match prints nothing); an id echoed with no command re-verifies nothing (01M4PPW8D8, both design critiques executed the gap); `open` names each reason. It is a floor for "may close", never a stop signal: ≤ 3 passes is a target, not a cap (D-355).
- `estimate_unseen` — Chapman's capture-recapture estimate over the two finders' candidate sets (`null` unless the slice has exactly two); advice for the
  re-dispatch brief, never a gate (`command-loop-performance.md` § 4.9 finding 18).

## Fallback

When the `Workflow` tool is absent from the session, or cannot load the script (a repo or checkout the sync has not reached, such as fabrik-lib), or the session is in the hub (D-961: the hub never calls the `Workflow` tool), or the operator did not invoke this run (the tool runs only on their explicit opt-in), the seats go out through the `Agent` tool in one message
with the same briefs and schemas, and the receipt's Pass row (or, with no receipt, the close's `--evidence`) names `shape: agent-tool`. Both shapes are the
same loop; the workflow is the one that keeps the lead's turns flat.

## Cobra notes (D-253)

Written beside the script's header; the two that matter most: `files_read` is the finder's own claim, so the
verify stage and the lead's Phase-2 execution are what catch a phantom read; the capture-recapture number is
advice and nothing in the record keys on it. The pin manifest is required: it was optional under D-663 until every launcher passed it (kaizen e29ffb101; `test_every_launcher_passes_a_pin_manifest` guards the launchers). The script has no filesystem, so a typed map of the right shape passes its check — the cheapest way around the pins now — and the pass reader's `read --pins` is what catches it: `UNPINNED` for a dir with no `MANIFEST.json`, `pins: NOT CHECKED` without the flag, either of which the receipt's Pass row must carry. The pins are checked at the two points the lead's tools can see, before dispatch and after the pass; a per-seat hash would need an agent after every seat and is not built — PIN MOVED attributes by mtime and seat span instead. `read --pins` mechanises the `/fabrik-review` Leak check for the live tree (status before and after the pass); the hand Leak check stays the authority for the stash list and for anything outside the repo.
