## Goal

Stop recommending AI models by guess. Build a suggester that, given a task profile
(`--task tts --volume-chars 130000 --quality-tier expressive --language en-GB …`),
returns Pareto-ranked candidates **from ONLY vendors Özgür has accounts / credits with**,
grounded in the live `kilo_agents.db` specialty catalog. Hard-fail with `exit=1` when no
data exists for the requested task class, so a session can never extrapolate from an empty
pool.

Three motivating failures from the driving session:

1. Recommended `google/gemini-3.1-flash-tts-preview` "via OpenRouter" without checking the
   live OR model list — the model is NOT on OR (live-verified 2026-07-05 by grep of the
   `/api/v1/models` snapshot).
2. Recommended Recraft ($0.04/image) over Flux-schnell ($0.003/image) for a children's
   flashcard bulk-cheap workload, anchored on the fabric `ai/20-vision.md` rule written
   for logo/branded work.
3. `docs/reference/kilo/CODING_SUBAGENT_SELECTION.md` exists and is auto-generated by
   `rank_coding_subagents.py`, but is **not referenced** anywhere in
   `.windsurf/rules/ai/00-ai-model-selection.md` — an orphan doc a fresh agent never
   sees.

## Chosen approach — three dependent phases in one spec

The three phases are **not independent** — B depends on A's seeded rows to have anything
to rank, and C depends on B's `*_SELECTION.md` files existing to reference them. So they
ship in one spec, one plan, one execution — Phase A → Phase B → Phase C in strict order.

### Phase A — Vendor-access catalog + close the specialty-catalog coverage gap

**Step 1 (before any DB seed):** write
`docs/reference/kilo/AI_VENDOR_ACCESS.md` — hand-editable table of vendor status per
Özgür's actual accounts. Header: a one-line `Last verified: YYYY-MM-DD` stamp so
staleness is visible. Columns:
`| Vendor | DB provider(s) | Auth mechanism (env var / OAuth / subscription) |
Status | Credits/quota remaining | Notes |`. The **DB provider(s)** column lists the
exact `agents.provider` values (e.g. `openai`, `anthropic`, `google`, `bfl`,
`recraft-ai`, `stability`, `elevenlabs`, `qwen`) that the seeder joins on — string-
matching is deterministic and cannot silently mis-map when a vendor rebrands.
`Status` is one of ✅ (accessible) / ⚠️ (accessible but low balance) / ❌ (no access).
**Both ✅ and ⚠️ count as accessible** — the seeder sets `reachable_with_existing_keys=1`
for their rows and the suggester includes them in candidate pools. ⚠️ is an operator
signal to top up soon, not a fence; the ranker surfaces a `low_balance` note in its
output for ⚠️ vendors so a session can pick a ✅ peer if one is on the frontier.
Rows are grouped by category (LLM gateways · Specialty vendors · Direct-API vendors ·
Web-only accounts). This file is the single source of truth for "accessible"
throughout Phases A/B/C — the Phase-A seeder reads it (no duplicate hardcoded
key-list). Auto-detecting balances is a separate future Phase B.5 spec (see Rejected #1).

### Phase B — Suggester CLI + per-task selection MDs

- **`engine/suggest_model.py`** (new). CLI:
  `python suggest_model.py --task {tts|stt|translation|image_gen|music_gen|llm|coding_llm}
  [--volume-chars N | --volume-minutes N | --volume-images N]
  [--quality-tier {cheap|balanced|expressive|premium}]
  [--language en-GB] [--top N] [--json]`
  Behavior:
  1. Parse `AI_VENDOR_ACCESS.md` for `Status: ✅` vendors — that's the accessible set.
  2. Query `kilo_agents.db` for `service_type=<task>` AND `status='active'` AND
     `reachable_with_existing_keys=1` AND provider is in the accessible set.
  3. If the candidate set is empty → print
     `NO DATA for task=<task> under accessible vendors — populate specialty catalog for
     this task class before suggesting.` and `exit(1)`.
  4. Otherwise: compute total cost using the volume flag (per-char / per-minute /
     per-image), Pareto-rank against `quality_elo` (if populated) + speed
     (`output_tokens_per_sec` / `perf_seconds`), and print the top-N Pareto-frontier
     candidates as a markdown table (or JSON with `--json`).
     **Mixed pricing_unit within a `service_type`** (e.g. `image_gen` has both
     `pricing_unit='image'` for BFL/Recraft/Stability rows and `pricing_unit='M-tokens'`
     for Google `gemini-*-image` and OpenAI `gpt-*-image` rows): the cost function
     normalizes to a per-workload total via a `PRICING_UNIT_HANDLERS` dispatch
     (`image → per_image × volume_images`; `M-tokens → input_cost_per_m ×
     avg_tokens_per_image / 1e6 × volume_images`). `avg_tokens_per_image` is a
     **hardcoded per-family dict inside `suggest_model.py`** (e.g. `google/gemini-*-image
     → 1290 tokens/image`, `openai/gpt-*-image → 1024 tokens/image`) — no new DB column,
     no per-row seed data. When the ranker encounters a token-billed row that isn't in
     the dict, it falls back to a safe over-estimate (2048 tokens/image) and prints a
     `stderr` warning naming the model so future runs can tighten the dict. This keeps
     the ranker comparable across billing models within one task class without expanding
     schema.
  5. Missing volume flag for a metered task-type → `exit(2)` with a `--volume-X flag
     required for --task <task>` message.
- **Per-task `*_SELECTION.md` generators**, each a small script alongside
  `rank_coding_subagents.py` (the existing exemplar):
  `rank_tts.py` → `docs/reference/kilo/TTS_SELECTION.md`
  `rank_stt.py` → `docs/reference/kilo/STT_SELECTION.md`
  `rank_translation.py` → `docs/reference/kilo/TRANSLATION_SELECTION.md`
  `rank_image_gen.py` → `docs/reference/kilo/IMAGE_GEN_SELECTION.md`
  All follow the pattern `rank_coding_subagents.py` establishes: a query → Pareto rank
  → write markdown. Each ranker is invoked by `daily_refresh.sh` so the MDs stay fresh.
  The rankers reuse `suggest_model.py`'s ranking function (single implementation).

### Phase E — Watch-list vendors + GPU providers catalog + upsell watcher

**Motivation (from post-CONVERGED session).** The user's stack is a moving target: today OR+Claude Max+Replicate+Soniox+DashScope covers everything cheaply, but a workload change (bulk Llama 3.3 70B inference, speed-critical bulk, fine-tuning) would make one of the four candidate vendors — Together.ai, Hyperbolic, Cerebras, Novita — pay back overnight. Same story for GPU rental: `fabrik-lib/gpu-rent/` already vendors Vast/RunPod/Modal, but their pricing isn't in any queryable catalog — you can't rank across them without hitting each provider's dashboard. Phase E fixes both: it seeds watch-list rows into `agents` (with `reachable_with_existing_keys=0` so the default suggester filter excludes them) + creates a `gpu_providers` table (per-hour pricing doesn't fit `agents.input_cost_per_m`) + adds a new "Watch-list" browser tab + writes `docs/reference/kilo/CANDIDATE_SIGNUPS.md` with break-even math + adds a rule-pack entry + grows the suggester to print a `💡 Consider signup:` line when a locked-out row Pareto-dominates the accessible frontier by ≥30%.

**Sub-steps:**

- **E.1 — `gpu_providers` table.** GPU rental prices per-hour by SKU, not per-M-tokens; forcing it into `agents` is a shape mismatch. New table:
  ```sql
  CREATE TABLE gpu_providers (
      id TEXT PRIMARY KEY,               -- 'vast/h100-80gb-spot', 'runpod/h100-80gb-community', ...
      provider TEXT NOT NULL,            -- 'vast','runpod','modal','hyperbolic','novita'
      gpu_sku TEXT NOT NULL,             -- 'H100-80GB','A100-80GB','H100-SXM','H100-PCIe','H200'
      tier TEXT NOT NULL,                -- 'spot','on_demand','reserved','per_second','bare_metal'
      usd_per_hour REAL,                 -- NULL for per-second providers (Modal); populate hourly equivalent too for cross-vendor ranking
      usd_per_second REAL,               -- Modal-style granularity
      cold_start_seconds REAL,           -- Modal <2s, RunPod 5–30s (observed); NULL = unknown
      reachable_with_existing_keys INTEGER NOT NULL DEFAULT 0,
      signup_trigger TEXT,               -- "> 24M tokens/day speed-critical" etc.
      notes TEXT,
      last_verified DATE
  );
  ```

- **E.3 — Browser GUI: full surface for every new column + new table.** The template auto-reads `SELECT *` so new columns land in the JSON payload, but the HTML template only renders columns with explicit `<th>` entries. **Real template architecture** (verified 2026-07-06 at `engine/models_browser_template.html:651-659` + JS `activeTab` variable at `:931`): tabs are `<span class="tab" data-tab="<name>">` chips in a selector strip; the single `<table>` body renders every row, and per-column visibility toggles based on `<th data-tabs="tab1 tab2 …">` matching the JS `activeTab` string. NO `<div id="tab-…">` sections exist. This phase adds:
  1. **New sortable column `Q-Elo`** (`data-sort="quality_elo" data-tabs="image voice"`) — Arena Elo for image_gen (ArtificialAnalysis) and tts (TTS Arena V2). NULL rows render as `—`.
  2. **New non-sortable badge column `Reach`** (`data-tabs="overview reasoning coding translation transcription voice image video ocr rent-gpu candidates"`) — green ✅ when `reachable_with_existing_keys=1`, dim ❌ when `=0`, yellow ⚠️ reserved (CSS class present but no row emits it this phase). Visible in EVERY tab so at-a-glance any row's accessibility is clear.
  3. **New tab chip `<span class="tab" data-tab="rent-gpu">`** rendering `gpu_providers` rows via a **separate `<tbody id="rows-gpu">`** because `gpu_providers.gpu_sku` / `usd_per_hour` / `usd_per_second` / `cold_start_seconds` columns don't map onto `agents` schema — a shared table would break sort/filter typing. When `activeTab==="rent-gpu"` the JS hides `#rows-agents` and shows `#rows-gpu`; every other tab does the opposite. Columns in the GPU tbody: `Provider | GPU SKU | Tier | $/hr | $/sec | Cold-start (s) | Reach | Signup trigger`. Default sort: `$/hr` ascending. Shows BOTH reachable states (Vast/RunPod/Modal accessible AND Hyperbolic/Novita candidate).

  5. **`signup_trigger`** — new `agents.signup_trigger TEXT` column (mirrors `gpu_providers.signup_trigger`) rendered in `candidates` tab and hovered as a `title` attribute on ❌ badges in every other tab.

  Coherence: SC #13 still checks `SELECT DISTINCT provider FROM gpu_providers WHERE reachable_with_existing_keys=1 == {vast, runpod, modal}`; the new `rent-gpu` tab surfaces both sides so you can see the SC-13 accessible set AND the locked-out set in one view. Existing tabs (LLM/image/voice/etc.) now show the `Reach` badge so a user reading the LLM tab immediately sees which of the 334 active LLM rows they can call today without new signup — the primary personal-use insight the whole plan exists to deliver.

Seeded from the E.1/E.2 rows plus the prose analysis captured in this session. - **E.5 — Rule pack entry.** Insert a `## Candidate signup vendors (watch-list — not currently active)` section into `.windsurf/rules/ai/00-ai-model-selection.md` after "Fabrik defaults." - **E.6 — Suggester upsell watcher.** After the default Pareto ranker prints its accessible frontier, run ONE more query against the full set (no accessibility filter), find the top row for the same task, and if it Pareto-dominates the accessible best by ≥30% on cost (and matches or exceeds quality where quality_elo is available), print a single `💡 Consider signup: <model> — <X>% cheaper for equivalent quality — needs new signup + payment method.` line to stderr. New `--strict` flag suppresses the upsell line for scripted pipelines. Threshold `UPSELL_MIN_SAVING_PCT = 0.30` is a module constant, tunable without schema change.

## Rejected alternatives

1. **Auto-detect vendor balances via API for every vendor at CLI-invoke time.** Rejected:
   Replicate has no public REST endpoint for account balance (2026-07-05, cited below —
   dashboard-only). Anthropic explicitly does not (community-requested feature open).
   Doing partial auto-detect for OR + ElevenLabs mixed with manual for everyone else
   creates two sources of truth. Manual-first, auto-detect as a separate future Phase B.5
   spec for the vendors that DO have an API (OR: `GET /api/v1/credits`; ElevenLabs:
   Creator-tier subscription page + `/user` endpoint).
2. **Split into three specs.** Rejected: A→B→C are a dependency chain (B queries A's
   rows; C references B's files). Splitting means three plan+review+execute cycles for
   one atomic capability — pure overhead. The `/fabrik-spec` Phase-0 decompose test asks
   whether each sub-project "produces working, testable software on its own"; Phase A
   alone produces seeded rows nothing consumes, and Phase C alone points at MDs that don't
   yet exist. They're not independent.
3. **Pre-commit enforcement script that fails a session if it recommends an unlisted
   model.** Rejected per user's explicit choice ("Advisory rule + programmatic hard-fail
   in suggester, NOT pre-commit script"). Rationale: recommendations happen in prose,
   which is hard to grep reliably without false-positives; the failure mode is
   session-scoped, not repo-scoped; and the CLI `exit=1` catches the real failure case
   (a session that tried to derive a recommendation from empty data).

## Open / blocking unknowns

**Open (Phase-A resolvable, not blocking spec):**

1. **CosyVoice English per-character price.** The public English pricing page describes
   billing "per character" but does not publish the per-language rate on the pages
   linked above. Resolution step in Phase A: probe the DashScope pricing API
   (`GET https://dashscope.aliyuncs.com/api/v1/services/aigc/multimodal-generation/pricing`
   or equivalent — actual endpoint to be confirmed at seed time) with the existing
   `DASHSCOPE_API_KEY`; if the endpoint returns nothing usable, seed the row with a
   conservative estimate (matched to `qwen-tts` at $0.00003/char) and add
   `estimate: True` to the PRICING entry so the drift test flags it for tightening.
2. **Deepgram STT streaming vs batch as separate rows or a `variant` column value.**
   The schema already has a `variant TEXT DEFAULT 'standard'` column. Resolution:
   seed as two rows with `variant='batch'` / `variant='streaming'`. Same pattern for
   AssemblyAI Universal-3 Pro.
3. **Where to put `quality_elo` for rows that don't appear in either Arena.** Resolution:
   leave `NULL`; the Pareto ranker treats NULL as "no quality signal" and ranks purely on
   cost + speed for those rows. Only rows with a quality signal contribute to the
   quality axis of the Pareto frontier. Explicit in `suggest_model.py`.
4. **Novita Llama 3.3 70B per-token rate (Phase E).** Not consistently published on public English pages surfaced this session. Resolution: Phase E seeder attempts a live probe against `https://api.novita.ai/v3/openai/models` (documented catalog endpoint) — if the response includes per-token price, use it; otherwise seed with a conservative estimate (parity with Hyperbolic's $0.40/M) and set `agents.notes = 'estimate — awaiting live probe'` so the future GPU-price scraper flags it for tightening. Non-blocking.
5. **Whether Together.ai gets a `fine_tuning` service_type row now (Phase E).** Resolution: no. YAGNI — spec explicitly excludes it (E.2). If a real fine-tune job appears, a follow-up ticket adds the service_type + row. Non-blocking.
6. **Whether the GPU pricing scraper (`scrape_gpu_prices.py`) needs auth (Phase E).** Resolution: all four vendor pricing pages cited in the External deps table load without auth (verified during this session's live fetches — no 401/403). Scraper runs anonymously; if a page later gates behind login, mark that vendor row `notes = 'stale — pricing page now gated'` and fall back to the previous value until an operator refreshes it. Non-blocking.
7. **Client-side JS click-sort correctness on the new Q-Elo column (Phase E.3).** Not verifiable from a script gate — the sort logic runs in the browser. Resolution: manual verification on first execution — open `models_browser.html`, click Image tab, click the Q-Elo column header, confirm rows reorder descending Elo (GPT Image 2 at top with 1339, then Reve 2.0, then MAI-Image-2.5). If broken, patch the JS sort registry in the template's `<script>` block. Non-blocking for phase gate; blocks final SC #18 sign-off.
