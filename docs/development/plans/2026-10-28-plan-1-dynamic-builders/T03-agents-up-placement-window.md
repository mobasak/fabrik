Invariants and touchpoints:
1. **Window targets by id (B12).** tmux resolves a window NAME target loosely — with only `agents-2` present, `-t =s:agents` and `-t =s:=agents` both select `agents-2` (executed by the review). Every window this script creates is captured by id (`new-session … -P -F '#{window_id}'`, `new-window … -P -F '#{window_id}'`); an existing window is found by an EXACT name match over `tmux list-windows -t "=$S" -F '#{window_id} #{window_name}'`; every later `split-window`, `select-layout`, `set -p`, `select-window` targets the id.
2. **Factored start (B-N3).** The branch at `scripts/sysadmin/agents_up.sh:591-624` becomes `start_grid`, called from the same place; for ≤ 4 builders its tmux effect is unchanged (one window `agents`, even-horizontal, `@agent` per pane, pane 0 selected). It sets `@agents_up_building <its own PID>` in the SAME tmux invocation as the `new-session` (chained with `\;`, before `@agents_up_root` is recorded, `:603-613`), so no `--window` poll can see the session without the flag; it unsets it (`set-option -u`) after its last pane AND in an `EXIT` trap. The flag counts as set only while that PID is alive (`kill -0 <pid>`), so a builder that died mid-build (a closed tab, the `exit 1` at `:610`, an OOM kill) reads "not building", as do a grid built before this change, an adopted grid (`:565-566`) and a grid `add` extends (plan-review pass 3, B-N4, B-N5).
3. **Placement on relaunch (D4; B11).** Builders, in the resolver's order, fill windows four PLACED panes at a time — the count is of panes actually created, never the loop index: a `split-window` or `new-window` that fails is said with the pane's command printed (the `:615-617` "no room" message) and the next builder takes that slot. Pane 5 (placed) opens `new-window -d -t "=$S:" -n agents-2 -c <dir> <cmd>`, panes 6-8 split it, pane 9 opens `agents-3`. After each pane: `select-layout -t <window id> even-horizontal`, `set -p -t <pane id> @agent <name>`.
4. **Grouped overflow sessions — the one rule (plan-review pass 2, class rewrite).** The overflow session for window `agents-<k>` is named `<S>+<k>`. `+` is outside the base-name alphabet `[A-Za-z0-9_-]` (`scripts/sysadmin/agents_up.sh:332-334`), so `<S>+<k>` can never be another repo's base session (tmux accepts the name: `has-session -t =a+2` exits 0, executed on the orchestrator's scratch server 2026-10-28) — the cross-repo collision class is gone, and a `<S>+<k>` session is this repo's by construction. D-1132's hand-made `fabrik-2` name was a mechanism; the ruling (four panes per tab, the rest in a further tab) is kept. Rules:
   - **At every grid start**, before the first pane, `start_grid` kills every session named `<S>+<k>` (`tmux list-sessions -F '#{session_name}'`, exact prefix `<S>+` then digits) — none can be grouped with a base session that does not exist yet, and a stale member of an old group keeps old windows and claude processes alive (a member survives killing its base — executed in pass 1).
   - **For each window k ≥ 2 after placement:** reuse `<S>+<k>` only when `has-session -t "=$S+$k"` succeeds AND its `#{session_group}` is NON-EMPTY AND equals `<S>`'s non-empty `#{session_group}`; otherwise `kill-session -t "=$S+$k"` (when present) and `new-session -d -t "=$S" -s "$S+$k"`; then `select-window` on `=<S>+<k>` to window `agents-<k>`'s id. A `<S>+<k>` whose window `agents-<k>` no longer exists is killed.
   - Finally `select-window` `<S>` to `agents`'s id and `select-pane` its pane 0, so `<S>`'s current window — tab 1's — is `agents` (W-14219e6f point 8, relaunch half).
   - The relaunch hint at `:590` names `tmux kill-session -t =<S>` and one `kill-session -t =<S>+<k>` per such session.
5. **`--window <n> <repo>`** (argument loop `:77-89`; n an integer ≥ 2, else usage exit 2). Resolves `<S>` (`:333-334`; the resolver's refusals refuse), then polls every 2 s for up to `FABRIK_AGENTS_WINDOW_WAIT_S` seconds (default 120) WHILE the session is absent or `@agents_up_building` holds a LIVE PID (B-N3, B-N4); still so at the bound → "the <S> grid was not ready within <n> s", exit 2. Then `owned_here` (`:548-574`) — a definite other owner refuses (B8). Window `agents-<n>` present (exact match): ensure `<S>+<n>` by invariant 4's rule, select its window, attach `=<S>+<n>` (the `:631-637` tail). Two concurrent `--window <n>` runs: the loser's failed `new-session -s <S>+<n>` re-reads the session and attaches when it is now grouped with `<S>`, else exits 2 naming it (plan-review pass 3). Absent: "the <S> grid has no window agents-<n> now — showing its current window", attach `=<S>`, never create `<S>+<n>`.

## Behavior Contract
- **Given** six registered builders and no session on a scratch tmux server, **When** the grid launches, **Then** window `agents` holds four panes, `agents-2` two, session `<S>+2` is created in `<S>`'s group with `agents-2` current, and `<S>`'s current window is `agents` (scripts/sysadmin/agents_up.sh:595-623; spec § The delta D4; plan-review pass 2, class rewrite)
- **Given** four or fewer builders, **When** the grid launches, **Then** there is one window `agents` and no `<S>+<k>` session (scripts/sysadmin/agents_up.sh:603-620)
- **Given** the second of six builders' `split-window` fails, **When** the grid launches, **Then** the failure is said with that pane's command and the remaining five fill `agents` (four) and `agents-2` (one) (scripts/sysadmin/agents_up.sh:615-617; plan-review pass 1, B11)
- **Given** a stale `<S>+2` grouped with an old killed base, a leftover `<S>+3`, and another repo's base session named `<S>-2`, **When** the six-builder grid launches, **Then** `<S>+2` is killed and re-created in the new group, `<S>+3` is killed, and `<S>-2` is untouched (scripts/sysadmin/agents_up.sh:332-334; plan-review pass 2, class rewrite)
- **Given** a server whose only window is `agents-2`, **When** the script looks up window `agents`, **Then** it finds none and targets nothing by that name (plan-review pass 1, B12)
- **Given** a grid up with window `agents-2` and either no `@agents_up_building` flag (built before this change) or a flag holding a dead PID, with `FABRIK_AGENTS_WINDOW_WAIT_S=2`, **When** `agents_up.sh --window 2 <R>` runs, **Then** it at once (never waiting the budget) ensures `<S>+2` in `<S>`'s group with `agents-2` current and attaches `=<S>+2`, while a session recording another repo's root refuses (spec § The delta D5; plan-review pass 1, B8; plan-review pass 2, B-N3; plan-review pass 3, B-N4)
- **Given** a grid up without `agents-3`, **When** `--window 3 <R>` runs, **Then** it says so, attaches `=<S>`, and creates no `<S>+3` (spec § The delta D5)
- **Given** `@agents_up_building` holding a live PID, then no session at all, with `FABRIK_AGENTS_WINDOW_WAIT_S=2`, **When** `--window 2 <R>` runs, **Then** both exit 2 saying the grid was not ready, and `--window 1` exits 2 with usage (spec § The delta D5; plan-review pass 2, B-N3)
