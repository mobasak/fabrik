# T03b — the disjointness check becomes a real one

## Scope
`--check` has always been CREDITED with proving parallel-set `owned_paths` disjointness, and spec r11 (D-117) proved by execution that it does not. `check_integrity` (`scripts/epic_order.py:108-124`) intersects `owned_paths` as SETS OF GLOB STRINGS, and only for pairs that each name the other in `parallel_with`. Two epics owning `src/app/**` and `src/app/models/**`, declared parallel, raise NO finding though they share every file under `models/`; two epics with the byte-identical glob and an EMPTY `parallel_with` raise none either, while `phased_order()` places them in the SAME phase — i.e. dispatched together. Replace both halves: compare epics by PHASE (the output of `phased_order()`, which is what actually determines concurrency) rather than by the author-declared `parallel_with`, and test real path overlap rather than string equality — **expand each glob against the real tree and intersect the resulting FILE SETS** — `git ls-files` filtered by a `/`-aware matcher — NOT bare `fnmatch`, which is separator-blind: `fnmatch('src/a/b/deep.py','src/a/*')` is **True** where `PurePath.match` is False, so a single-`*` glob would swallow whole subtrees. Translate explicitly (`**`→`.*`, single `*`→`[^/]*`) or use `PurePath.match` with a `**` pre-pass, then a set intersection. Do NOT normalise to a literal directory prefix: the live epics already own paths like `libs/**/product_entitlements_bridge/**`, whose literal prefix is just `libs/`, so a prefix test would report an overlap with every other epic touching anything under `libs/` — a false finding on real data, which is how a check earns its way back into being ignored. Realised file sets are exact, cheap on a repo this size, and degrade honestly: ⚠️ **realised sets ALONE fail open on the design's primary case.** Epics are authored BEFORE the code (spec § Personas step 2), so on a new repo two epics both owning `src/app/**` realise to ∅, `∅ ∩ ∅ = ∅`, no finding — while `phased_order()` puts both in phase 1 and dispatches them together, which is exactly what this ticket's first contract row must catch. So the test is the UNION of two predicates: the realised-set intersection AND a pattern-level subsumption check (glob-vs-glob, `**`-aware), the second of which fires when neither glob matches an existing file. There is no non-blocking channel to report the empty case through — `main()` exits `1 if findings else 0` and `findings` is the only output — so do not try to 'note' it; either it is a finding or it is silent. Keep the single-migration-owner check, re-keyed to phases the same way — and note it then stops reading `parallel_with` entirely, so add a finding for "`parallel_with` contradicts `phased_order()`". **The T03a alternative is withdrawn: it is unreachable at execution time** — T03a merges at Merge Order 5 and this ticket at 6, so by the time a coder reads this, T03a is already merged and cannot be re-scoped. ⚠️ **`phased_order()` RAISES on a cycle** (`scripts/epic_order.py:137`), and today `--check` returns before ever calling it (`:170-179`), so a cyclic `depends_on` currently exits cleanly. Calling it from `check_integrity` makes `--check` die on an uncaught traceback instead — and T05b is about to wire that into `final_gate.py`, which expects a pass/fail row. Wrap the phase lookup in `try/except ValueError` and convert a cycle into its own finding. This is a smoke test becoming a real one, so the two cases above are the watched-red ones. ⚠️ **Shares `check_integrity` with T03a** — the Depends edge serialises them. ## Behavior Contract
- **Given** two epics in the same `phased_order()` phase whose paths overlap — either as different globs (`src/app/**` vs `src/app/models/**`) or as identical globs with an EMPTY `parallel_with` — **When** `--check` runs, **Then** each case reports the overlap; today the first raises nothing and the second is never compared at all (scripts/epic_order.py:115)
- **Given** an epic owning `libs/**/product_entitlements_bridge/**` and another owning `libs/**/other/**` in the same phase, **When** `--check` runs, **Then** NO finding is raised — their realised file sets are disjoint even though both literal prefixes are `libs/` (scripts/epic_order.py:115)
- **Given** two epics in DIFFERENT phases with overlapping paths, **When** `--check` runs, **Then** no finding is raised — they never run concurrently (scripts/epic_order.py:127)
- **Given** two epics in one phase that both own migration globs, **When** `--check` runs, **Then** the single-migration-owner finding still fires, now keyed on the phase rather than on `parallel_with` (scripts/epic_order.py:119)
- **Given** an epic set whose `depends_on` edges form a CYCLE, **When** `--check` runs, **Then** it reports a named integrity finding and exits non-zero rather than raising — today `phased_order()` raises `ValueError` (scripts/epic_order.py:137) and `--check` returns at `:170` before ever calling it, so a cyclic set exits 0 (scripts/epic_order.py:137)
