### 12-FACTOR (all twelve axes)
- I codebase: shared code → fabrik-lib, never two apps in one repo
- II deps: every shelled-out binary installed + pinned in the Dockerfile
- III config: granular env vars; no secrets in code; no grouped env sets
- IV backing services: swappable by DSN/config change only
- V build/release/run: releases immutable; never hot-patch a container
- VI processes: stateless; session state → redis-main; no sticky sessions
- VII port binding: bind in-container; Traefik routes; no host ports:
- VIII concurrency: scale out; never daemonize or write PID files
- IX disposability: SIGTERM returns in-flight jobs to the queue; jobs idempotent
- X dev/prod parity: same backing services everywhere; no SQLite-for-Postgres
- XI logs: unbuffered stdout only; the app never writes/rotates a logfile
- XII admin: migrations/one-offs run against the deployed release, never startup

## Findings

### F1 — the never-lower guard failed OPEN on an unreadable limit · C9 · CONFIRMED · FIXED
`[ "$live" -ge "$target" ]` with an empty `$live` does not return false — it ERRORS (exit 2,
`integer expression expected`). Both guard tests then fail, `verb` stays `SET`, and the script issues
`docker update` at the table's target. On a container whose real ceiling was HIGHER, that LOWERS it — the
precise outcome the never-lower rule exists to prevent. The read can genuinely fail: the container can be
removed between the existence check one line above and this call, and this link has measured intermittency
(spec C5). Proven by executing the comparison:

```
$ live=""; target=268435456
$ [ "$live" -ge "$target" ]; echo $?
/bin/bash: [: : integer expression expected
2
$ verb=SET; [ "$live" -ne 0 ] && verb=RAISE; echo $verb
SET          # ← falls through to the update
```

**Severity is raised by F1a (below): Docker provides no never-lower guarantee of its own** — it refuses only
a decrease below CURRENT USAGE, which is far weaker — so this bash comparison is the only thing there is.
**Fix:** a `case "$live" in ''|*[!0-9]*)` guard that SKIPS and counts a failure. Grader:
`test_an_unreadable_limit_is_skipped_rather_than_overwritten`, red on the pre-fix script.

### F1a — the test fixture is STRICTER than reality · C5 · CONFIRMED · documented, not "fixed"
The fake `docker update` refuses ANY decrease; real Docker refuses only a decrease below current usage.
Asked whether any test passes only because of that gap: **no** — `test_it_never_lowers_an_existing_ceiling`
asserts `not any("loki" in u for u in env.updates())`, i.e. that no CALL was made at all, so it grades the
bash guard and never reaches the fake's strictness. The honest conclusion is recorded in the test docstring:
the never-lower property rests entirely on the script, and nothing on Docker.

the entire index. On a tree with three concurrent Claude sessions that is every file any other session has
staged — and the script PUSHES afterwards.

It is not theoretical: it is what happened to this change, twice over, mid-review.
