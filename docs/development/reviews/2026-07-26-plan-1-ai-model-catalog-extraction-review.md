## Why this review is shaped around one class

Every engine import in the retained set is wrapped in `try/except`. So the failure mode of a wrong
excise is **not** a crash — it is exit 0 with silently degraded output that then fleet-syncs to 47
project copies. That is behavior 1's flagship risk, and it is invisible to any gate that only asks
"did it run?". The review therefore prioritises orphaned-consumer detection over everything else.

The same class already bit twice during planning, which is why the KEEP set stopped being prose:

- the plan retained `rank_task_subagents.py` while deleting `build_task_baselines.py` and
  `derive_cost.py`, which it imports;
- it retained `check_daily_refresh_freshness.py` while deleting the `alerting/` package it needs to
  raise the alarm — the alarm's own dependency.

Both are one graph traversal away and neither is visible by reading. The KEEP/DELETE set is now
computed by `scripts/kilo-benchmarks/tests/excise_manifest.py`, whose `--check` fails when any
retained file depends on a deleted one.

## Findings

**R2-1 — CONFIRMED, and it is the one that mattered.** D.1's scripted step-removal collapses `if`
blocks whose THEN body is emptied — but not an emptied **ELSE**. `wsl_startup_hook.sh:129` guarded the
kilo/embedding workflow with `if FABRIK_DISABLE_KILO_WORKFLOW; then echo skipped; else <the engine
pipeline>; fi`. Removing the pipeline left `else` → `fi` with no body, which bash rejects.

⚠️ **`bash -n` on the whole file PASSED.** The hook's pipeline runs as an extracted child block, and
only that block is invalid. It was caught by `test_golden_parity.py::test_the_hook_child_block_is_syntactically_valid`
— a RETAINED oracle whose own docstring says *"nothing else validates this file's inner block"*.
Had the excise dropped that test (an earlier draft of the remnant did), the boot pipeline would have
failed silently at every shell open. FIXED: the vacuous construct removed; 81/81 green.

**R2-2 — CONFIRMED.** `excise_manifest.py` deleted ITSELF on the first run: it lives under `tests/` and
was not a KEEP root, and the plan called it *"throwaway, deleted with the engine tree"*. But gate (c)
is manifest-aware, so without the tool the post-excise residue check cannot run at all. FIXED: added
as a root, with the reason recorded in the file.

**R2-3 — CONFIRMED.** Gate (c)'s original pattern matched any `scripts/kilo-benchmarks/*.py` and so
could never reach empty while the remnant exists — a retained file being referenced by the retained
hook is CORRECT. FIXED: the gate now flags references to **deleted** scripts only, built from git's
actual deletion record. Behavior 4: **0 hits**.

**R2-4 — CONFIRMED.** 15 docs referenced deleted engine scripts. Repointed to `engine/…`; cross-repo
paths de-linked (a markdown link cannot resolve into another repo) and retired-script rows dropped.
