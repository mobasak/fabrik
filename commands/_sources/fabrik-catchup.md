This command never reconciles a doc or contract itself — it routes to `/fabrik-doc-converge`, `/fabrik-features`, `/fabrik-data-contract` and `/fabrik-ui-design`, each of which owns its own convergence loop.

## ⚠️ Termination contract

You are done **only when a fresh re-run of Phase 0 MEASURE raises zero new queue items** — each prior finding is fixed, explicitly `BLOCKED`, or **accounted for** (these count on re-measure as named, not as new items, once this run's report names it): a candidate dead consumer reference or a genuinely undecidable reconcile downgraded per Phase 2 (both report-only, un-committed); an item ROUTED to whoever owns it — mailed to its beat, or a gate red or work item reported to its owner — with the mail id or owner named; an item another session holds, named. The re-measure must be a genuine no-op **and** `python scripts/final_gate.py --check --json` reports `"status":"success"` **in this same run** — or reds only on checks a named owner holds (`GATE: failure (owned: <owner>)`). Executing one item can surface another, so the pass in which you executed any queue item is never the last MEASURE: run Phase 0 again, unprompted, before you stop. Three thoughts that each mean *run the re-measure now*: "the queue looked short," "that fix was trivial," "it's obviously caught up." Catchup owns only this outer loop — never the inner convergence loop of a routed command (that command's own termination contract governs its own no-op). **Context is never a reason to stop**: the harness auto-compacts and the run continues in the same invocation. The only legitimate early stop is a routed command coming back `BLOCKED` after 3 consecutive attempts on the same item — pause that item, name it in the report, and work the rest.

## Phase 0 — MEASURE (read-only; no fixes yet)

If `/opt/fabrik/docs/infrastructure/probe-reports/fleet-doc-audit-latest.md` exists (the hub's weekly `scripts/fleet_doc_audit.py` sweep) and has a flagged row for this project, read it as a head start — **never as a substitute**: the report can be up to a week stale, so every number in it still needs the fresh check below. If the path is unreadable (a non-hub box, or the file hasn't run yet), skip it — it is a head start, not a dependency.

Run `python scripts/final_gate.py --check --json` FIRST and queue each red it reports as an item. Before fixing a red, look for its owner — an open item in `.fabrik/work/` that names the failing check, or a sibling mid-flight on that file: an owned red is reported to its owner (and, in a worktree, to the merge owner), never fixed here.

Run every probe against the CURRENT tree. Probes 2-4 mirror `scripts/fleet_doc_audit.py`'s probe set project-side; probes 1, 5, 6 and 7 EXTEND it, so scoping this run down to the audit's three probes would silently drop them:

1. **Plan state vs lock.** Enumerate BOTH plan shapes, excluding anything under `docs/development/plans/archived/`: single-file plans `docs/development/plans/*.md` and plan-set dirs `docs/development/plans/*/` (the same-stem spine file). Read each `Status:` through `parse_plan_status` (`python3 -c "import sys; sys.path[:0] = ['/opt/fabrik/scripts', 'scripts']; from docs_updater import parse_plan_status; print(parse_plan_status(__import__('pathlib').Path(sys.argv[1]))[0])" <plan file or spine .md>`; the hub's copy first), — the value the gate's tools act on, which a grep misreads on a bold or decorated header. Look up `.fabrik/plan-locks/<file-or-dir-stem>.json` if it exists and reconcile against ALL `.fabrik/plan-locks/*`, so no lock is left unmatched to a live plan. Flag: spine `IN-PROGRESS` with the lock missing or not `"active"`; spine `DRAFT`/`CONVERGED` with an `active` lock; spine `EXECUTED` while the plan (file or dir) sits outside `docs/development/plans/archived/`; a lock whose `plan` path does not resolve, or sits under `docs/development/plans/` outside `archived/` with a terminal `status` (a plan kept elsewhere, such as an epic's, is not held to the `archived/` rule), or sits INTO `docs/development/plans/archived/` while `"active"`. Terminal allowlist: {`released`, `executed`, `complete`, `completed`, `done`} (allowlist-not-denylist per fabrik-lib `f8249ec3`: an unknown word leaves a lock flagged for a human; measured live 2026-08-29, `executed` is the MOST COMMON terminal and the old `released`/`complete` example would have mis-flagged four finished locks). **Not a finding:** a lock INTO `docs/development/plans/archived/` with a terminal `status`.
2. **Key-doc freshness vs code.** `git log -1 --format=%ct -- <code roots>` vs the same for every registry-obligated key doc (`docs/SERVICES.md`, `docs/RESILIENCE.md`, `docs/CONFIGURATION.md`, `docs/DEPLOYMENT.md`, `docs/FEATURES.md` — only the ones this `project.yaml::type` actually obligates). The code roots are the top-level directories `git ls-files -- '*.py' '*.ts' '*.tsx' '*.js' | grep / | cut -d/ -f1 | sort -u` prints, less `tests`, `docs`, `templates`, dot-directories and a `libs/` only when it is vendored (a first-party one stays) — never a hand list (`tryton_modules/` and `sao-overlay/` sit outside `src app web lib scripts`). ≥14 days behind = a CANDIDATE, queued only when a spot check finds a claim the code contradicts; a date-stale doc with no drift is named in the report, not queued.
3. **Stub sentinels.** Run `python3 /opt/fabrik/scripts/fleet_doc_audit.py --repo .` and read its `stubs:` line, never a hand list. It reports `<DOC>.md (template text left: p%)` for a doc left as its scaffold template (at least half of some version of that template is still in it, and template text is at least half of the doc), else `<DOC>.md (<n>)` for the seed sentinels it still holds. With no `/opt/fabrik`, grep for `[Project Name]`, `[TBD…]`, `**Last Updated:** YYYY-MM-DD`, `[… — fill in]`, `[purpose]` and say the template check was skipped.
4. **Untracked key docs.** An obligated doc on disk that `git ls-files` doesn't know is its own failure mode, never folded into the staleness day-count.
5. **Spec `shape:` vs code.** For each `specs/services/*.yaml`, check every `shape:` flag against the code, per `CLAUDE.md` § Spec contract awareness (`needs_database` ⇒ a real DB call, `exposes_metrics` ⇒ live `/metrics`, `needs_cache` ⇒ a real Redis call, …).
6. **Candidate dead consumer references (DETECT only — never docker-probe, never auto-fix).** Grep this project's own `.env`/`.env.example`/specs/code for a retired-looking host/service name: a known-retired service, an `/opt/archived/*` source, or an env row naming a service absent from the hub's `PORTS.md`/catalog. **Report these for the operator — do not act on them.** This box's **local** `fabrik` bridge is not the fleet's, so a project-side probe can falsely call `postgres-main:5432` dead: liveness is **hub-verified only**. The captcha retirement (`docs/SERVICES.md` § Service-status drift warning) is the cautionary case: a catalog row can outlive its service, so neither "the row says it's live" nor a project-side probe saying "unreachable" is proof — only a hub-side check settles it. Actual retirement (once the operator confirms) routes to `/fabrik-decommission`, the hub-side retirement runbook — never remove or repoint a reference from inside this command.
7. **Work-store hygiene** (a repo with `.fabrik/work/`). An open item titled as a markdown heading or opening with a closed marker is a polluted queue entry: `grep -lE '"title": "(#|✅|~~|\*\*CLOSED)' .fabrik/work/W-*.json | xargs -r grep -LE '"status": "(done|dropped)"'` lists them. An owned one goes to its owner (`work.py drop` if finished, a retitle if live; an open item or a live sibling is an owner); an unowned one is dropped or retitled here — never close another owner's item.

## Phase 1 — QUEUE (worst-first, routed)

Turn Phase 0's findings into one ordered list, worst first: a gate red first (it holds the termination gate), then a plan-state contradiction or candidate dead consumer reference, which outrank a 15-day-stale doc, which outranks a stub sentinel or a polluted work item. Every item names the finding, its evidence (`path:line` or command output) and its **route**:

| Finding class | Route |
|---|---|
| A scaffold doc stale/missing/stubbed (SERVICES, RESILIENCE, CONFIGURATION, OPERATIONS, QUICKSTART, DEPLOYMENT, TROUBLESHOOTING, INDEX.md, docs/README.md, README.md, BUSINESS_MODEL, STRATEGIC_BACKLOG) | `/fabrik-doc-converge <doc>` |
| `docs/FEATURES.md` incomplete or stale | `/fabrik-features` |
| `docs/data-contract.md` stale vs the live schema | `/fabrik-data-contract` |
| `docs/ui-design.md` stale vs the built screens (GUI types only) | `/fabrik-ui-design` |
| Plan `Status:` vs lock, or a `shape:` flag lying vs code | a named reconcile action: fix whichever side is wrong to match reality (the spine header or lock; flip the flag in `specs/services/<id>.yaml` to match the code, or fix the code to match an intentionally-true flag), never both silently, stating which and why; genuinely undecidable → report-only per Phase 2 |
| Gate red (Phase 0) | the fix its check names; one an open item or a live sibling owns is reported to its owner, never fixed here |
| Work-store item polluted (probe 7) | its owner: a finished item is dropped by its owner or the distributor (`work.py drop`), a live one retitled; this command never closes another owner's item |
| Candidate dead consumer reference | **report only, no auto-fix**: name it and why it looks retired, once the operator confirms, retirement routes to `/fabrik-decommission` (hub-side runbook); this command never docker-probes liveness or removes/repoints from a project |

## Phase 2 — EXECUTE (one item at a time)

Work the queue top to bottom. **In a repo with `.fabrik/work/`, claim before executing:** a queued item an open store item already names is claimed by its id (`python3 scripts/work.py claim W-xxxxxxxx`), its commit names that id, and `work.py done W-xxxxxxxx --evidence <sha>` closes it; one another session holds is skipped and named. Mint no item for a finding without one. In the hub, an item on another agent's beat is mailed to that beat (`docs/reference/agents/`) instead of executed, and the mail id goes in the report. Per item: run its routed command or reconcile action, re-run the exact probe that raised it, then commit — explicit pathspecs only, Agent Provenance Trailers, **one commit per item** (never batch unrelated items into one commit — a bisect needs the granularity). **A DECISION-SHAPED reconcile** (a deliberate `shape:` flag flip, a Status re-ruling — beyond restoring observed truth) **carries its `docs/DECISIONS.md` row IN THE SAME commit, classified at mint** (the SAME-change law; plain row normally — a reconcile is by construction reversible; a truth-restoring correction needs no row). **A reconcile whose true side is genuinely undecidable from the tree downgrades to a REPORT-ONLY item naming both candidate truths** — the most-reversible disposition (manifesto Invariant 3), never a silent guess. A routed command owns its own termination contract (e.g. `/fabrik-doc-converge` converges to its own edit-free no-op): catchup dispatches to it, moves to the next queue item once it reports done, and never re-implements that command's convergence loop itself. **Exception:** a candidate dead consumer reference is never auto-executed — it stays a reported, un-committed item; move to the next queue item once it is named in the report (retirement is the operator's call, run hub-side via `/fabrik-decommission`).
