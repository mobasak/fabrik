## ⚠️ Termination contract — coverage-adjudicated (READ FIRST — the rule agents skip)

This is a LOOP that runs **until no issues remain to raise AND every class is proven hunted** — two conditions, BOTH required, neither sufficient alone. A quiet round alone is not the exit (that *sample* found nothing ≠ nothing exists). A fully-adjudicated checklist alone is not the exit either (adjudication without a confirming quiet round is premature). The exit needs BOTH:

**Before Pass 1 — three mechanical obligations, in order:**
1. **Anchor:** read the NEWEST `docs/development/reviews/*-review.md` for this scope (if any). Compute the surface hash: `git rev-parse HEAD` + `git diff HEAD | md5sum`. If it matches the prior report's recorded `Surface:` line, this run **re-adjudicates THAT report's checklist** (verification + delta only — a new finding must name the rubric class it belongs to, or it is a rubric gap to report). Unchanged surface + previously fully-adjudicated checklist = a short verification report, honestly. ⚠️ **A prior `Surface:` that is not a comparable hash — a PATH (`Surface: plan set docs/…/`, which is what a `/fabrik-execute-plan` integration receipt writes), a commit RANGE (`a..b`), or a prose description — CANNOT match, by construction. Do not let that degrade silently into "no prior report": say in the report that the anchor did not match and WHY, then run the full WIDE pass 1.** The distinction is load-bearing because the two paths differ in rigour — a match routes you into verification-and-delta and lets you INHERIT the prior checklist's rows, and inheriting a `CLEAN` row that was wrong is exactly how a defect survives a review that ran.
2. **Rubric:** run `python scripts/review_rubric.py --changed <paths>` and paste its verbatim output into the report inside a fenced block — the class rows derive from IT, never from memory.
3. **Persist:** create `docs/development/reviews/YYYY-MM-DD-<scope>-review.md` NOW, with the `Surface:` hash line and the Coverage Checklist skeleton. **A review that exists only in chat does not exist** — `check_review_coverage.py` (run by `final_gate` and the stop-hook) reads only this file; the review is INVALID until the adjudicated checklist + Pass Ledger live in it.

The Coverage Checklist: one row per failure class from the rubric output (FLOOR + MATCHED + workflow checklist), PLUS the standing recurrence classes: **fail-open vs fail-closed on every gate/guard · cost/quota/limit accounting edges (unknown≠0, per-call vs batch) · boundary/sentinel/prefix collisions · behavior-without-a-test**. Every row starts `UNCHECKED`.

**The round SHAPE — for reviews whose surface is a DIFF (a changed-file set):** pass 1 is a **WIDE sweep** — every class in the rubric partition is assigned to a finder in the SAME round; a round that samples a subset is not a pass-1. Round 1 is the ONLY full pass (D-207) and it FIXES THE PARTITION: every later pass is the round-1 seats re-verifying their OWN slices — the fix hunks in the slice plus one hop of callers and callees (fixes are the least-reviewed code in any loop, and the severest escapes sit in functions the fix never edited) — never a fresh whole-artifact reader; the two-pass minimum stays: a quiet round 1 is confirmed by a closing pass in which those seats CONFIRMED every claim of their slice ledgers executed true and zero code or doc defects (D-206, D-335). The closing round's FINDERS run in a **non-author context** (`62-using-subagents.md` § Role separation defines independent; adjudication stays with the orchestrator). **Commands whose surface is NOT a diff — journeys/personas/states (`/fabrik-user-test`, `/fabrik-service-test`), the spec↔plan INVENTORY (`/fabrik-conformance-review`), and the whole-repo unit inventory (`/fabrik-repo-review` — on a clean tree `git diff HEAD` is EMPTY and its md5 anchors nothing) — keep their own loop shapes unchanged; nothing in this paragraph rewrites a certification gauntlet. Their `Surface:` hash is `git rev-parse HEAD` + a hash of the enumerated inventory, since there is no diff to hash.**

**THE SCOPE PARAGRAPH — D4 and D5 govern every DELTA round any consumer of this contract runs; the exemption above governs a consumer's round-1 SURFACE and its hash, not how a later round counts or is sized.** `/fabrik-review` and `/fabrik-repo-review` run D-207's delta rounds; a certification gauntlet or the inventory review runs a DELTA round only where its own text names one as such — its confirming round (a FULL round by its own Phase text) is not a delta round and D5 never resizes it — and every obligation below (the exit row, the ledger grammar, the finder-return rule, the gates) binds all five consumers alike. WHAT A DELTA ROUND MAY COUNT — the bounded hop (D4, D-230): a CONFIRMED defect of a delta round is a defect of a line INSIDE the previous round's fix hunks, or a live contradiction those hunks created with a sentence of the same section; a defect one hop out — a caller, a callee, a neighbouring section, a pre-existing claim — is RECORDED with a named destination (a backlog row, a mail, a sibling ticket) and never counted, even when real and executed, so the ledger's `confirmed:` and the record's `--confirmed` count the SAME thing. SIZED BY THE SLICES (D5, D-335 superseding D-229): every later pass dispatches one seat per slice whose ledger holds an open claim — a failing claim, a claim the fix introduced, or any claim not yet EXECUTED true (which is why a quiet round 1 still owes its closing pass) — on the seat that owned that slice in round 1 (the same model, or Sonnet/Haiku where the slice is not risky); a slice with no open claim is not re-dispatched, and a refuted or recorded candidate opens nothing; `dispatch_headroom.py --slices` (or `--units`) sizes round 1 and the union of the round-1 seats is the ceiling of every later pass (the floor of D-208 binds round 1 only).

**Round zero — the orchestrator's OWN pre-pin probe (D7, D10 — D-231), before any finder sees a delta:** the fix's mutation battery (rule 4) runs only on a copy and under an explicit `timeout` at or above its own measured runtime — a battery killed mid-mutation leaves the copy, never the tree, neutered; every added line is re-read WHOLE (length, citations, claims); the CLASS of the fix is swept — the siblings of the shape at every mirror site — because a round whose finders confirm only residue of the previous round's fix is the signal to sweep the class, not to run another round; the Pass Ledger's `method:` cell APPENDS `; round-zero probe — <what>` to its re-derivation text on the row that records it (a cell reading only the probe fails the coverage gate's re-derivation row rule). Five rules bind the probe: (1) **ANY CLAIM WITH A CHECKABLE REFERENT IS A SCRIPT, NOT PROSE — and that includes every claim YOUR OWN FIX introduces.** A claim about what a verb, a window or a reach-back does, AND every count, enumeration, line anchor or negative, is executed at round 1 as a probe script pinned beside the receipt (`<scratchpad>/<review>/probes/<claim>.sh`, its output pasted under the claim), re-run and re-cited when the claim changes, and never re-derived by a finder. ⚠️ **A RE-READ IS NOT EXECUTION** — `proxy-never-evidence` says so, and a count is not checked by looking at it again. ⚠️ **COBRA (D-253):** the cheap way to satisfy this without doing it is to write corrections carrying no checkable claims at all, so the obligation is discharged EQUALLY by DELETING an unverifiable claim — the cheap path and the compliant path are the same one, and `denominator-honesty` already forbids a count without its population, so vagueness buys nothing either; (2) **THE PRE-PIN SWEEP IS A COMMAND** — `python3 scripts/enforcement/check_review_hygiene.py --surface <pin> --claim <term>` lists every mirror site of a rewritten claim; read each before the pin and APPEND `· mirrors: <n> read` to that row's `method:` cell after its re-derivation text (a `claim` row pasted into the receipt is dispositioned `RECORDED — measured (<n> mirrors read)`, never FIXED); (3) **TWO CONSECUTIVE RESIDUE PASSES FORCE A REWRITE** — when two consecutive delta rounds confirm only defects inside the previous round's hunks, the next edit rewrites the affected paragraph or function from the probe's output in ONE batch instead of a third patch, and the row's method cell APPENDS `; class rewrite — <paragraph>`; when that residue is itself a sentence that RESTATES, COUNTS or PARTITIONS what another artifact owns, the rewrite is a DELETION — the sentence goes, replaced by at most a pointer to where the fact is re-derivable, never by a re-cut of the claim; a sentence left in place with a citation appended is not a deletion, and is the cheapest way to look compliant while the restatement goes on drifting; a third residue pass without a rewrite is the non-convergence breaker's foundation error, named in the `## BLOCKED` question. (4) **A GRADER IS PROVEN BY ITS RED, NEVER BY ITS GREEN** — every mutant a fix names is asserted dead by the NAME of the failing test on a fresh copy of the pin, environment-bound tests deselected and `__pycache__` purged; the battery mutates EVERY CLAUSE THE FIX ADDS, not only the lines its graders cite; each grader is proven it CAN fail by REMOVING THE GUARD, never by breaking an expression inside it — an exception that lands in the surrounding handler makes a SOUND grader look weak; a fix landing in both a function and its CLI half is graded on EACH half EVEN WHEN THE FUNCTION HALF IS ALREADY GREEN, because a dead function-level mutant says nothing about the argparse block; and a round that EDITS a test file states the grader NAMES it removed and added AND every grader whose BODY it changed (`^def test_`, `func Test`, or `^\s*(test|it)(\.each)?\(` — whichever pattern the suite's language uses; that last one needs `grep -E`/`rg`, since in default BRE it exits nonzero and a pipe reads it as a clean ZERO), never a bare count, because a DELETED grader leaves no red — and the cheapest bypass is not a deletion at all but a BODY-ONLY edit, a gutted assertion or a `skip` marker, which changes no name and leaves both lists honestly empty; so each name AND each changed body is paired with the mutant it was proven red on. (5) **A GRADER OBSERVES ITS SUBJECT THROUGH THE CONSUMER'S ENTRY POINT AND MODE** — a fix to a checker or a gate is graded by driving its real entry point over a fixture that EXHIBITS the condition and one that does not, and ASSERTING on the output token the fix itself adds, in every mode the consuming contract reads (a gate fix that reaches the human renderer but not `--json` is not done). A difference the two fixtures already carried stays green with the fix reverted and has observed nothing. Never assert on a regex, a constant or the source text the subject happens to contain, and never only from the test file that ships beside the module.

Loop passes as specified (finders → refute → prove & fix → regression-guard), updating rows as you go. **You are DONE only when ALL of these hold:**
- **The final round is QUIET — `confirmed: 0 · fixed: 0 · unexecuted: 0` (D-206) — with every candidate ever raised adjudicated** (CLEAN / FIXED / REFUTED / RECORDED). Write all FIVE counters on the ledger row (`found: F, new: N, confirmed: C, fixed: X, unexecuted: U` — `check_review_coverage.py`'s own order): the graders parse the `found:`/`fixed:` PAIR — a Pass-shaped row missing either is REFUSED as unparseable, and a row carrying neither counter is worse: it parses to NOTHING and the exit round becomes invisible to the graders entirely (`check_convergence.py` QUIET_PASS; `check_review_coverage.py` `_unparsed_pass_lines`); `found:`/`new:` stay as RECALL counters; `confirmed:` is the EXIT counter (D-206) and the stall-breaker below keys on it — `check_convergence.py` refuses a flip whose LAST Pass row does not read `confirmed: 0` once the ledger carries the counter, and `check_review_coverage.py` grades a receipt's last row by it (`_confirmed_quiet`). (Certification gauntlets keep their OWN final-row grammar — `cert-execution`'s `new inventory: 0 · new findings: 0 · fixes applied: 0` — this row shape governs DIFF-surface reviews. The two DO co-render in /fabrik-user-test and
/fabrik-service-test, and a cert report carrying a Coverage Checklist is ALSO graded by
`check_file` — so its ledger rows must be labelled `Pass k` (never a bare `| 2 |` or `| Round 2 |`)
and carry the `found:`/`fixed:` pair; the cert counters (`new inventory`/`new findings`/`fixes
applied`) ride the SAME row as extra columns. ⚠️ Do NOT model this on an existing cert report — the prevailing shape puts the colons in the
HEADER and bare numbers in the cells (`| Pass | found: | new: | fixed: |`), which `_pass_counters`
cannot read, so the exit-round check never fires at all.) (Quote this contract phrase only inside a fence — the literal pair is grader-visible anywhere in the report body.) Canonical row shape — METHOD FIRST, counters ADJACENT, finders after: `| Pass k | method: citation|re-derivation|gate | found: 0, new: 0, confirmed: 0, fixed: 0, unexecuted: 0 | finders: <manifest> |` — the graders bind SAME-LINE, not ordering (D-053: no character windows): keep the whole row on ONE line, the counters in the grader's own order — `found:`, then `new:`, then `confirmed:`, then `fixed:`, `unexecuted:` last (`check_review_coverage.py`'s `_COUNTER_NAMES`; it refuses a displaced `new:` or `confirmed:` by name, and `check_convergence.py`'s quiet-row regex reads `found: 0`/`confirmed: 0` before `fixed: 0`) — and the method cell anywhere on it. A round that raised 3 FRESH candidates and refuted all 3 IS quiet under D-206 (`new: 3, confirmed: 0` — the refutations are executed disproofs in the ledger, never a reason for another round). A re-raise of a candidate an earlier round ALREADY ADJUDICATED (a standing DESIGN-GAP row, an unbuilt endpoint) is **CITED in its disposition-ledger row, never counted** — `found:` counts only candidates NEEDING adjudication, so the honest converged round reads `found: 0` while the re-raise stays visible. **The scope of "already adjudicated" is the disposition STILL HOLDING:** for a REFUTED row that is its quoted proof — a re-raise carrying evidence the proof does not cover NEEDS adjudication and COUNTS (an independent finder rediscovering a weakly-refuted bug must never be silenced by the citation rule; if the proof covers it, cite the proof).
- **Every row is adjudicated** — `CLEAN` (hunted this run, with what/where evidence), `FIXED(n)`, or `REFUTED(n, proof)`. No `UNCHECKED` rows. An in-scope CONFIRMED or PLAUSIBLE finding terminates FIXED or REFUTED — never silently passed.{{RESIDUAL}}
- **The last code-changing pass was followed by a confirming re-check** of every class its fixes touched (fixes introduce defects — the pass that changed code is never the last look at those classes). **A spot-verify of the fixes is that re-check step — it is NEVER the closing round**.
- **Every dispatched finder has RETURNED and been adjudicated** — a round whose manifest shows `returned < dispatched` may be recorded but can NEVER be the exit round, and "covered by the orchestrator" is a NON-QUIET state: the orchestrator is the AUTHOR. A finder still running is an OPEN question, not an absent one; a finder that DIED is re-dispatched. Nothing in the harness distinguishes slow from hung for you, so the loop waits or re-dispatches — it never closes over an outstanding finder.
- **Mechanical gates are green** (`final_gate`) — lint/type/test classes are the gates' job; do not spend finder passes re-discovering what a gate catches. **The gate section of the artifact is RE-MEASURED in the closing pass, never inherited** from an earlier pass's attribution.
- **Ledger reproduced** — numbered passes with `found:` (counting every candidate RAISED that NEEDS adjudication — later-refuted FRESH candidates included; a re-raise of an already-adjudicated STANDING row is CITED in its disposition row, never counted — D-206), `new:` (candidates first raised THAT round — never raised, in any adjudication state, by an earlier round), `confirmed:` (candidates you EXECUTED and that held — the exit counter, D-206; the stall breaker below keys on it), `fixed:` and `unexecuted:` per pass, **and each row names its FINDERS** (which pool units + which native agents were dispatched for THAT round) **plus a `method` cell, written WITH its label (`method: citation` | `method: re-derivation` | `method: gate` — the graders anchor on the label). The CLOSING pass is a RE-DERIVATION pass — a different METHOD, not just a fresh read: re-derive every count, enumeration and anchor from its primary source, and the exit REQUIRES at least one row naming `method: re-derivation` — `check_review_coverage.py` (`_REDERIVATION_ROW`) HARD-BLOCKS any changed review artifact without one; convergence under a single method is method-stability, not truth.** A row with no finder manifest is not a pass. **The manifest counts dispatched AND returned — a finder that DIES (stream watchdog, API stall, null return) has swept NOTHING:** its partition stays un-swept until re-dispatched or covered by the orchestrator, and the row says so (`dispatched: 3, returned: 1, partitions re-covered: 2`). Silently counting a dead finder's partition as swept is how a review loses two-thirds of its recall and still stamps converged. **A verification/spot-verify run is labelled `VERIFY`, never numbered as a pass** — writing `found: 0, fixed: 0` for a finder round that never ran is a FABRICATED row. Forged evidence is worse than an honest non-quiet exit, because the gates machine-read these rows.

**Minimum two passes, ALWAYS** — the pass that first completes the checklist is never the exit pass: the closing pass (the round-1 seats confirming their own slices' ledgers — a DELTA pass where the consumer runs delta passes, its own FULL confirming round otherwise, as the scope paragraph above assigns per consumer) must re-adjudicate it (and may re-open classes). Accuracy and the run's declared budget are ONE objective: once `command_run.py start` declares the budget (D-335 — to build), a pass that would overrun it closes with `handoff`, its failing slices and claims named in the ledger, never runs on.

**There is no round CAP (D-330, which supersedes D-321) — and no pass without an open claim.** While a slice's ledger holds an open claim its owning seat's next pass is owed; a refuted or recorded candidate opens nothing (D-206, D-230); a slice whose claims still fail after its third pass is handed off with those claims NAMED — never a pass four over the whole artifact — and a run that would overrun the budget `start` declares (D-335 — to build) closes with `handoff`, the failing slices named. **Stall circuit-breaker (measured non-progress is a VERDICT, never a reason for round N+1):** if 3 consecutive later rounds (whatever shape the scope paragraph above assigns the consumer) show non-decreasing **and nonzero** `confirmed:` counts, STOP and emit `## BLOCKED: NON-CONVERGENCE` naming the suspected foundation error (a design claim, a contract, the decomposition) — the defect lives UPSTREAM of the surface; re-ground it, then resume. This is NOT a ceiling: rounds stay unbounded while `confirmed:` is falling; a refute-everything round can never trip it (refuted candidates never count, D-206); an all-zero streak (`confirmed: 0 · fixed: 0 · unexecuted: 0` rounds — re-raised already-adjudicated candidates are cited in their rows, never counted, D-206) is CONVERGENCE, never a stall — the breaker measures CONFIRMED-defect pressure, and zero pressure is the goal state (oscillation is the per-finding 3-attempt escalation's job, below). The only non-quiet stop a review FINDING may cause (the scope-growth stop below stops on SCOPE, not on a finding) is a **BLOCKED escalation**: a specific finding that survived **3 consecutive fix attempts** (same test failing three times) → pause THAT finding, post it to the operator (Telegram / report `## BLOCKED` section naming the finding + the 3 attempts), and keep looping on everything else. (The safety HARD STOP below, the scope-growth stop below and the stall circuit-breaker above are the separate, non-finding exceptions.) An agent never self-exits with an "accepted risk" — unresolved means BLOCKED-and-escalated, visible to the operator, not declared away. Re-invoking this command on unchanged code re-adjudicates this SAME checklist — free-hunting outside it must be justified as a new class, which is a rubric gap to report. A delta seat's brief carries the previous seat's REFUTED list verbatim — a refuted candidate re-raised by a fresh seat costs a round for nothing. **Scope-growth stop — COUNTED:** every delta round reports how many of its CONFIRMED defects lay inside code or prose THIS REVIEW added in an earlier round rather than inside the original diff: `python3 scripts/command_run.py round --confirmed <c> --own-fix <n> …`. **TWO OF THE LAST THREE rounds at or above TWO-THIRDS own-fix (`--own-fix * 3 >= --confirmed * 2`, `--confirmed` > 0) is the stop** — the fix grew the surface: route that surface to `/fabrik-spec` (or a backlog row with a named destination) and converge on the ORIGINAL diff; the loop converges a diff, it never designs one. ⚠️ **The stop is on SCOPE, never on an outstanding defect.** The superseded EQUALITY bar made "the surface is quiet" a theorem — `own-fix == confirmed` meant zero original-surface defects by construction. A ratio does not: up to a third of a qualifying round's confirmed defects can still be on the original surface. So the stop suspends new HUNTING and never the close: every confirmed defect still open at the stop — ANYWHERE in the three-round window, its NON-qualifying round included, which by construction holds the largest SHARE of original-surface defects — a share, not necessarily the largest count — is NAMED at the stop and fixed; the remainder rounds re-verify THAT FIXED SET and nothing else, so they terminate — a further own-fix defect one of them raises is `RECORDED — measured` onto the routed backlog row and never re-arms this stop. The receipt's last row must still satisfy D-206 (`confirmed: 0 · fixed: 0 · unexecuted: 0`). Only work that is genuinely OWN-FIX takes the backlog exit above. **Every DELTA round states `--own-fix`** (round 1 is the full pass: state `--own-fix 0`); a round that did not state it OCCUPIES its slot in the three-round window and can never be one of the two qualifying rounds — the window never slides past it, so the stop stays computable and round 1's legitimate omission simply does not qualify. Making the flag required on a delta round is `command_run.py`'s job and is routed there by D-278; its advisory now computes THIS bar (D-281) and MAY print one of three verdicts, never before the third round and never on a converging loop — read the verdict rather than re-deriving the window, and remember that silence is not a verdict. ⚠️ **COBRA (D-253):** the cheapest dodge is to hold residue findings back so qualifying rounds never fall together — which is why the window is TWO OF THREE and not two consecutive — and the cheapest dodge of all is simply to omit the counter, which is why the flag's enforcement is routed rather than asserted here. The MIRROR dodge is to over-classify — calling an original-surface defect own-fix both trips the stop sooner and buys it the backlog exit — so own-fix is EVIDENCED, never asserted: each finding's row cites the round whose fix hunk contains the line (`own-fix: round k`), checkable against that round's md5 pair. D-278 supersedes D-252 and carries the measurement; the figures live there because a rendered corpus cannot hold a number that moves. ⚠️ The STALL BREAKER cannot make this stop — it keys on a count that stops FALLING, and this failure mode produces a falling count while nothing about the original diff improves.

Run every owed pass **UNPROMPTED, inside THIS ONE invocation** — never end the turn with `UNCHECKED` rows or an unconfirmed fix for the operator to re-invoke. You return control EXACTLY ONCE: at the fully-adjudicated checklist. **The one exception is a safety HARD STOP** — you discover you are about to touch production / shared data or fire a destructive action against real data: halt immediately, even with `UNCHECKED` rows left. Safety outranks completing the loop; that halt is a legitimate stop, not an incomplete turn. **Context is never a reason to stop:** the harness AUTO-COMPACTS long conversations and the run continues in the same invocation — keep durable artifacts current and keep going; "low context" filed as BLOCKED is still the named violation, and a heavy remainder is dispatched to fresh subagents, never deferred. Post-compact, the SessionStart hook auto-injects a recent-context recap, and the `session-recall` MCP (`search_chats` / `get_chat`) recovers any detail the summary dropped — use it instead of re-deriving or guessing.
