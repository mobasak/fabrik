## ⚠️ Termination contract — coverage-adjudicated (READ FIRST — the rule agents skip)

This is a LOOP that runs **until no issues remain to raise AND every class is proven hunted** — two conditions, BOTH required, neither sufficient alone. A quiet round alone is not the exit (that *sample* found nothing ≠ nothing exists). A fully-adjudicated checklist alone is not the exit either (adjudication without a confirming quiet round is premature). The exit needs BOTH:

**Before Pass 1 — three mechanical obligations, in order:**
1. **Anchor:** read the NEWEST `docs/development/reviews/*-review.md` for this scope (if any). Compute the surface hash: `git rev-parse HEAD` + `git diff HEAD | md5sum`. If it matches the prior report's recorded `Surface:` line, this run **re-adjudicates THAT report's checklist** (verification + delta only — a new finding must name the rubric class it belongs to, or it is a rubric gap to report). Unchanged surface + previously fully-adjudicated checklist = a short verification report, honestly. ⚠️ **A prior `Surface:` that is not a comparable hash — a PATH (`Surface: plan set docs/…/`, which is what a `/fabrik-execute-plan` integration receipt writes), a commit RANGE (`a..b`), or a prose description — CANNOT match, by construction. Do not let that degrade silently into "no prior report": say in the report that the anchor did not match and WHY, then run the full WIDE pass 1.** The distinction is load-bearing because the two paths differ in rigour — a match routes you into verification-and-delta and lets you INHERIT the prior checklist's rows, and inheriting a `CLEAN` row that was wrong is exactly how a defect survives a review that ran. Reported by trade-intelligence (`01M14R1RS2`) after a post-execute-plan `/fabrik-review` re-swept from scratch and found 3 real defects in code the plan receipt's own 2-pass ledger had marked CLEAN hours earlier — the right outcome, reached by a failed string compare rather than by design.
2. **Rubric:** run `python scripts/review_rubric.py --changed <paths>` and paste its verbatim output into the report inside a fenced block — the class rows derive from IT, never from memory.
3. **Persist:** create `docs/development/reviews/YYYY-MM-DD-<scope>-review.md` NOW, with the `Surface:` hash line and the Coverage Checklist skeleton. **A review that exists only in chat does not exist** — `check_review_coverage.py` (run by `final_gate` and the stop-hook) reads only this file; the review is INVALID until the adjudicated checklist + Pass Ledger live in it.

The Coverage Checklist: one row per failure class from the rubric output (FLOOR + MATCHED + workflow checklist), PLUS the standing recurrence classes: **fail-open vs fail-closed on every gate/guard · cost/quota/limit accounting edges (unknown≠0, per-call vs batch) · boundary/sentinel/prefix collisions · behavior-without-a-test**. Every row starts `UNCHECKED`.

**The round SHAPE — for reviews whose surface is a DIFF (a changed-file set):** pass 1 is a **WIDE sweep** — every class in the rubric partition is assigned to a finder in the SAME round; a round that samples a subset is not a pass-1. Middle passes (2 … N-1) are **SCOPED**: each re-checks only the fix diff PLUS its callers and callees — fixes are the least-reviewed code in any loop, and the severest escapes sit in functions the fix never edited. The **closing pass is a FULL fresh sweep — non-negotiable**: the unbounded fresh round is the loop's RECALL mechanism; what the scoped middle removes is one full sweep per fix, never the full sweep itself (net: **1 wide + k scoped + 1 wide**, instead of k+1 wide). The closing round's FINDERS run in a **non-author context** (`62-using-subagents.md` § Role separation defines independent; adjudication stays with the orchestrator). **Commands whose surface is NOT a diff — journeys/personas/states (`/fabrik-user-test`, `/fabrik-service-test`) and the spec↔plan INVENTORY (`/fabrik-conformance-review`) — keep their discovery-until-dry loop unchanged; nothing in this paragraph rewrites a certification gauntlet. Their `Surface:` hash is `git rev-parse HEAD` + a hash of the enumerated inventory, since there is no diff to hash.**

Loop passes as specified (finders → refute → prove & fix → regression-guard), updating rows as you go. **You are DONE only when ALL of these hold:**
- **The final round is QUIET — `found: 0 · new: 0 · fixed: 0` — with every candidate ever raised adjudicated** (CLEAN / FIXED / REFUTED). Write all THREE counters on the ledger row: the graders parse the `found:`/`fixed:` PAIR — a Pass-shaped row missing either is REFUSED as unparseable, and a row carrying neither counter is worse: it parses to NOTHING and the exit round becomes invisible to the graders entirely (`check_convergence.py` QUIET_PASS; `check_review_coverage.py` `_unparsed_pass_lines`); `new:` is the CONTRACT's stall-breaker counter — no grader reads it, this loop does, so write it too. (Certification gauntlets keep their OWN final-row grammar — `cert-execution`'s `new inventory: 0 · new findings: 0 · fixes applied: 0` — this row shape governs DIFF-surface reviews. The two DO co-render in /fabrik-user-test and
/fabrik-service-test — the diff-vs-non-diff scoping above decides which final row applies, so there
is no pick to make.) (Quote this contract phrase only inside a fence — the literal pair is grader-visible anywhere in the report body.) Canonical row shape — counters ADJACENT, finders after: `| Pass k | found: 0 | new: 0 | fixed: 0 | finders: <manifest> |` — `check_convergence.py`'s QUIET_PASS window caps the found→fixed gap at 40 chars, so a finder manifest wedged between the counters silently fails an honest quiet round. A round that raised 3 FRESH candidates and refuted all 3 is NOT quiet (`new: 3`) — run the next full round. A re-raise of a candidate an earlier round ALREADY ADJUDICATED (a standing DESIGN-GAP row, an unbuilt endpoint) is **CITED in its disposition-ledger row, never counted** — `found:` counts only candidates NEEDING adjudication, so the honest converged round reads `found: 0` while the re-raise stays visible. **The scope of "already adjudicated" is the disposition STILL HOLDING:** for a REFUTED row that is its quoted proof — a re-raise carrying evidence the proof does not cover NEEDS adjudication and COUNTS (an independent finder rediscovering a weakly-refuted bug must never be silenced by the citation rule; if the proof covers it, cite the proof).
  ⚠️ **History of this clause — two corrections, both load-bearing.** 2026-08-27 (transdoc): the exit demanded `found: 0` counting re-raises, making termination UNREACHABLE while any standing row stayed true — the exit was re-keyed on `new:`. 2026-08-31 (D-048): that left `found > 0` finals that FAIL the graders (`check_convergence.py` QUIET_PASS demands the `found: 0 · fixed: 0` pair; `check_review_coverage.py` demands a quiet FINAL ledger row) — reconciled by cite-not-count: the re-raise is recorded, never counted, so honesty and the graders agree. Nothing unadjudicated can escape either way, and open rows still block `/fabrik-release`.
- **Every row is adjudicated** — `CLEAN` (hunted this run, with what/where evidence), `FIXED(n)`, or `REFUTED(n, proof)`. No `UNCHECKED` rows. An in-scope CONFIRMED or PLAUSIBLE finding terminates FIXED or REFUTED — never silently passed.{{RESIDUAL}}
- **The last code-changing pass was followed by a confirming re-check** of every class its fixes touched (fixes introduce defects — the pass that changed code is never the last look at those classes). **A spot-verify of the fixes is that re-check step — it is NEVER the closing round** (live defect: a loop closed on "round 11 spot-verify only" after a class-level fix, leaving the post-fix surface without its full fresh sweep).
- **Mechanical gates are green** (`final_gate`) — lint/type/test classes are the gates' job; do not spend finder passes re-discovering what a gate catches.
- **Ledger reproduced** — numbered passes with `found:` (counting every candidate RAISED that NEEDS adjudication — later-refuted FRESH candidates included; a re-raise of an already-adjudicated STANDING row is CITED in its disposition row, never counted — D-048), `new:` (candidates first raised THAT round — never raised, in any adjudication state, by an earlier round; the stall breaker below keys on it) and `fixed:` per pass, **and each row names its FINDERS** (which pool units + which native agents were dispatched for THAT round). A row with no finder manifest is not a pass. **The manifest counts dispatched AND returned — a finder that DIES (stream watchdog, API stall, null return) has swept NOTHING:** its partition stays un-swept until re-dispatched or covered by the orchestrator, and the row says so (`dispatched: 3, returned: 1, partitions re-covered: 2`). Silently counting a dead finder's partition as swept is how a review loses two-thirds of its recall and still stamps converged (web-ecommerce-factory, 2026-08-29: 5 finder deaths in one day at the harness's 600s no-progress watchdog, accumulated findings discarded — the survivor proved the work fits in ~260s, so the deaths were stalls, not oversized briefs). **A verification/spot-verify run is labelled `VERIFY`, never numbered as a pass** — writing `found: 0, fixed: 0` for a finder round that never ran is a FABRICATED row (live confession: "I labelled a verification run as a pass — that's a fabricated row, which is the thing the ledger exists to prevent"). Forged evidence is worse than an honest non-quiet exit, because the gates machine-read these rows.

**Minimum two full rounds, ALWAYS** — the round that first completes the checklist is never the exit round: a fresh, independent round (on a diff surface: the closing FULL sweep, non-author finders per the round SHAPE above) must re-adjudicate it (and may re-open classes). Accuracy outranks pass-count.

**There is NO round ceiling.** While anything is still being raised, the next round is owed — 5, 15, 30 rounds; the loop runs until the exit conditions hold. **Stall circuit-breaker (measured non-progress is a VERDICT, never a reason for round N+1):** if 3 consecutive rounds show non-decreasing **and nonzero** `new:` counts, STOP and emit `## BLOCKED: NON-CONVERGENCE` naming the suspected foundation error (a design claim, a contract, the decomposition) — the defect lives UPSTREAM of the surface; re-ground it, then resume. This is NOT a ceiling: rounds stay unbounded while `new:` is falling; a refute-everything round is the success path (`new:` falls to 0 next round) and can never trip it; an all-zero streak (`found: 0 · new: 0 · fixed: 0` rounds — re-raised already-adjudicated candidates are cited in their rows, never counted, per D-048) is CONVERGENCE, never a stall — the breaker measures fresh-candidate pressure, and zero pressure is the goal state (oscillation is the per-finding 3-attempt escalation's job, below). The ONLY non-quiet stop a review FINDING may cause is a **BLOCKED escalation**: a specific finding that survived **3 consecutive fix attempts** (same test failing three times) → pause THAT finding, post it to the operator (Telegram / report `## BLOCKED` section naming the finding + the 3 attempts), and keep looping on everything else. (The safety HARD STOP below and the stall circuit-breaker above are the separate, non-finding exceptions.) An agent never self-exits with an "accepted risk" — unresolved means BLOCKED-and-escalated, visible to the operator, not declared away. Re-invoking this command on unchanged code re-adjudicates this SAME checklist — free-hunting outside it must be justified as a new class, which is a rubric gap to report.

Run every owed pass **UNPROMPTED, inside THIS ONE invocation** — never end the turn with `UNCHECKED` rows or an unconfirmed fix for the operator to re-invoke. You return control EXACTLY ONCE: at the fully-adjudicated checklist. **The one exception is a safety HARD STOP** — you discover you are about to touch production / shared data or fire a destructive action against real data: halt immediately, even with `UNCHECKED` rows left. Safety outranks completing the loop; that halt is a legitimate stop, not an incomplete turn. **Context is never a reason to stop:** the harness AUTO-COMPACTS long conversations and the run continues in the same invocation — keep durable artifacts current and keep going; "low context" filed as BLOCKED is still the named violation, and a heavy remainder is dispatched to fresh subagents, never deferred. Post-compact, the SessionStart hook auto-injects a recent-context recap, and the `session-recall` MCP (`search_chats` / `get_chat`) recovers any detail the summary dropped — use it instead of re-deriving or guessing.
