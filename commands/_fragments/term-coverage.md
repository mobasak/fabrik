## ⚠️ Termination contract — coverage-adjudicated (READ FIRST — the rule agents skip)

This is a LOOP that runs **until no issues remain to raise AND every class is proven hunted** — two conditions, BOTH required, neither sufficient alone. A quiet round alone is not the exit (that *sample* found nothing ≠ nothing exists). A fully-adjudicated checklist alone is not the exit either (adjudication without a confirming quiet round is premature). The exit needs BOTH:

**Before Pass 1 — three mechanical obligations, in order:**
1. **Anchor:** read the NEWEST `docs/development/reviews/*-review.md` for this scope (if any). Compute the surface hash: `git rev-parse HEAD` + `git diff HEAD | md5sum`. If it matches the prior report's recorded `Surface:` line, this run **re-adjudicates THAT report's checklist** (verification + delta only — a new finding must name the rubric class it belongs to, or it is a rubric gap to report). Unchanged surface + previously fully-adjudicated checklist = a short verification report, honestly. ⚠️ **A prior `Surface:` that is not a comparable hash — a PATH (`Surface: plan set docs/…/`, which is what a `/fabrik-execute-plan` integration receipt writes), a commit RANGE (`a..b`), or a prose description — CANNOT match, by construction. Do not let that degrade silently into "no prior report": say in the report that the anchor did not match and WHY, then run the full WIDE pass 1.** The distinction is load-bearing because the two paths differ in rigour — a match routes you into verification-and-delta and lets you INHERIT the prior checklist's rows, and inheriting a `CLEAN` row that was wrong is exactly how a defect survives a review that ran. Reported by trade-intelligence (`01M14R1RS2`) after a post-execute-plan `/fabrik-review` re-swept from scratch and found 3 real defects in code the plan receipt's own 2-pass ledger had marked CLEAN hours earlier — the right outcome, reached by a failed string compare rather than by design.
2. **Rubric:** run `python scripts/review_rubric.py --changed <paths>` and paste its verbatim output into the report inside a fenced block — the class rows derive from IT, never from memory.
3. **Persist:** create `docs/development/reviews/YYYY-MM-DD-<scope>-review.md` NOW, with the `Surface:` hash line and the Coverage Checklist skeleton. **A review that exists only in chat does not exist** — `check_review_coverage.py` (run by `final_gate` and the stop-hook) reads only this file; the review is INVALID until the adjudicated checklist + Pass Ledger live in it.

The Coverage Checklist: one row per failure class from the rubric output (FLOOR + MATCHED + workflow checklist), PLUS the standing recurrence classes: **fail-open vs fail-closed on every gate/guard · cost/quota/limit accounting edges (unknown≠0, per-call vs batch) · boundary/sentinel/prefix collisions · behavior-without-a-test**. Every row starts `UNCHECKED`.

**The round SHAPE — for reviews whose surface is a DIFF (a changed-file set):** pass 1 is a **WIDE sweep** — every class in the rubric partition is assigned to a finder in the SAME round; a round that samples a subset is not a pass-1. Round 1 is the ONLY full pass (D-207); every later round is a DELTA over the previous round's fix diff plus one hop of callers and callees — fixes are the least-reviewed code in any loop, and the severest escapes sit in functions the fix never edited — and the two-round minimum stays: a quiet round 1 is confirmed by a closing delta round that carried a fresh non-authoring seat and CONFIRMED zero code or doc defects (D-206). The closing round's FINDERS run in a **non-author context** (`62-using-subagents.md` § Role separation defines independent; adjudication stays with the orchestrator). **Commands whose surface is NOT a diff — journeys/personas/states (`/fabrik-user-test`, `/fabrik-service-test`), the spec↔plan INVENTORY (`/fabrik-conformance-review`), and the whole-repo unit inventory (`/fabrik-repo-review` — on a clean tree `git diff HEAD` is EMPTY and its md5 anchors nothing) — keep their own loop shapes unchanged; nothing in this paragraph rewrites a certification gauntlet. Their `Surface:` hash is `git rev-parse HEAD` + a hash of the enumerated inventory, since there is no diff to hash.**

**THE SCOPE PARAGRAPH — D4 and D5 govern every DELTA round any consumer of this contract runs; the exemption above governs a consumer's round-1 SURFACE and its hash, not how a later round counts or is sized.** `/fabrik-review` and `/fabrik-repo-review` run D-207's delta rounds; a certification gauntlet or the inventory review runs a DELTA round only where its own text names one as such — its confirming round (a FULL round by its own Phase text) is not a delta round and D5 never resizes it — and every obligation below (the exit row, the ledger grammar, the finder-return rule, the gates) binds all five consumers alike. WHAT A DELTA ROUND MAY COUNT — the bounded hop (D4, D-230): a CONFIRMED defect of a delta round is a defect of a line INSIDE the previous round's fix hunks, or a live contradiction those hunks created with a sentence of the same section; a defect one hop out — a caller, a callee, a neighbouring section, a pre-existing claim — is RECORDED with a named destination (a backlog row, a mail, a sibling ticket) and never counted, even when real and executed, so the ledger's `confirmed:` and the record's `--confirmed` count the SAME thing. SIZED BY THE FIX (D5, D-229): every later round dispatches by the size of the previous round's fix diff — changed lines, the review receipt excluded — at or under 20 changed lines ONE fresh non-authoring seat plus the hygiene script; above it, the round-1 partition over the touched slices; `dispatch_headroom.py --delta <n>` beside the round-1 `--slices` or `--units` prints it (the floor of D-208 binds round 1 only, D-229).

**Round zero — the orchestrator's OWN pre-pin probe (D7, D10 — D-231), before any finder sees a delta:** a mutation battery runs only on a copy and under an explicit `timeout` at or above its own measured runtime — a battery killed mid-mutation leaves the copy, never the tree, neutered (01M25Y93M); every mutant a fix names is asserted dead by the NAME of the failing test on a fresh copy of the pin, environment-bound tests deselected and `__pycache__` purged; every added line is re-read WHOLE (length, citations, claims); the CLASS of the fix is swept — the siblings of the shape at every mirror site — because a round whose finders confirm only residue of the previous round's fix is the signal to sweep the class, not to run another round; the Pass Ledger's `method:` cell APPENDS `; round-zero probe — <what>` to its re-derivation text on the row that records it (a cell reading only the probe fails the coverage gate's re-derivation row rule). Three rules bind the probe: (1) **THE MECHANISM IS A SCRIPT, NOT PROSE** — a claim about what a verb, a window or a reach-back does is executed at round 1 as a probe script pinned beside the receipt (`<scratchpad>/<review>/probes/<claim>.sh`, its output pasted under the claim), re-run and re-cited when the claim changes, and never re-derived by a finder; (2) **THE PRE-PIN SWEEP IS A COMMAND** — `python3 scripts/enforcement/check_review_hygiene.py --surface <pin> --claim <term>` lists every mirror site of a rewritten claim; read each before the pin and APPEND `· mirrors: <n> read` to that row's `method:` cell after its re-derivation text (a `claim` row pasted into the receipt is dispositioned `RECORDED — measured (<n> mirrors read)`, never FIXED); (3) **TWO CONSECUTIVE RESIDUE PASSES FORCE A REWRITE** — when two consecutive delta rounds confirm only defects inside the previous round's hunks, the next edit rewrites the affected paragraph or function from the probe's output in ONE batch instead of a third patch, and the row's method cell APPENDS `; class rewrite — <paragraph>`; a third residue pass without a rewrite is the non-convergence breaker's foundation error, named in the `## BLOCKED` question.

Loop passes as specified (finders → refute → prove & fix → regression-guard), updating rows as you go. **You are DONE only when ALL of these hold:**
- **The final round is QUIET — `confirmed: 0 · fixed: 0 · unexecuted: 0` (D-206) — with every candidate ever raised adjudicated** (CLEAN / FIXED / REFUTED / RECORDED). Write all FIVE counters on the ledger row (`found: F, new: N, confirmed: C, fixed: X, unexecuted: U` — `check_review_coverage.py`'s own order): the graders parse the `found:`/`fixed:` PAIR — a Pass-shaped row missing either is REFUSED as unparseable, and a row carrying neither counter is worse: it parses to NOTHING and the exit round becomes invisible to the graders entirely (`check_convergence.py` QUIET_PASS; `check_review_coverage.py` `_unparsed_pass_lines`); `found:`/`new:` stay as RECALL counters; `confirmed:` is the EXIT counter (D-206) and the stall-breaker below keys on it — `check_convergence.py` refuses a flip whose LAST Pass row does not read `confirmed: 0` once the ledger carries the counter, and `check_review_coverage.py` grades a receipt's last row by it (`_confirmed_quiet`). (Certification gauntlets keep their OWN final-row grammar — `cert-execution`'s `new inventory: 0 · new findings: 0 · fixes applied: 0` — this row shape governs DIFF-surface reviews. The two DO co-render in /fabrik-user-test and
/fabrik-service-test, and a cert report carrying a Coverage Checklist is ALSO graded by
`check_file` — so its ledger rows must be labelled `Pass k` (never a bare `| 2 |` or `| Round 2 |`)
and carry the `found:`/`fixed:` pair; the cert counters (`new inventory`/`new findings`/`fixes
applied`) ride the SAME row as extra columns. ⚠️ Do NOT model this on an existing cert report:
of the 25 cert reports on the box (measured 2026-08-31), ZERO carry a parseable `found: N`/`fixed: M`
pair on a `Pass k` row — the prevailing shape puts the colons in the HEADER and bare numbers in the
cells (`| Pass | found: | new: | fixed: |`), which `_pass_counters` cannot read, so `ordered_rows`
is empty and the exit-round check never fires at all.) (Quote this contract phrase only inside a fence — the literal pair is grader-visible anywhere in the report body.) Canonical row shape — METHOD FIRST, counters ADJACENT, finders after: `| Pass k | method: citation|re-derivation|gate | found: 0, new: 0, confirmed: 0, fixed: 0, unexecuted: 0 | finders: <manifest> |` — the graders bind SAME-LINE, not ordering (D-053 re-grounding: the old 40/160-char windows made cell order load-bearing and failed honest compliant rows — both caps removed): keep the whole row on ONE line, the counters in the grader's own order — `found:`, then `new:`, then `confirmed:`, then `fixed:`, `unexecuted:` last (`check_review_coverage.py`'s `_COUNTER_NAMES`; it refuses a displaced `new:` or `confirmed:` by name, and `check_convergence.py`'s quiet-row regex reads `found: 0`/`confirmed: 0` before `fixed: 0`) — and the method cell anywhere on it. A round that raised 3 FRESH candidates and refuted all 3 IS quiet under D-206 (`new: 3, confirmed: 0` — the refutations are executed disproofs in the ledger, never a reason for another round). A re-raise of a candidate an earlier round ALREADY ADJUDICATED (a standing DESIGN-GAP row, an unbuilt endpoint) is **CITED in its disposition-ledger row, never counted** — `found:` counts only candidates NEEDING adjudication, so the honest converged round reads `found: 0` while the re-raise stays visible. **The scope of "already adjudicated" is the disposition STILL HOLDING:** for a REFUTED row that is its quoted proof — a re-raise carrying evidence the proof does not cover NEEDS adjudication and COUNTS (an independent finder rediscovering a weakly-refuted bug must never be silenced by the citation rule; if the proof covers it, cite the proof).
- **Every row is adjudicated** — `CLEAN` (hunted this run, with what/where evidence), `FIXED(n)`, or `REFUTED(n, proof)`. No `UNCHECKED` rows. An in-scope CONFIRMED or PLAUSIBLE finding terminates FIXED or REFUTED — never silently passed.{{RESIDUAL}}
- **The last code-changing pass was followed by a confirming re-check** of every class its fixes touched (fixes introduce defects — the pass that changed code is never the last look at those classes). **A spot-verify of the fixes is that re-check step — it is NEVER the closing round** (live defect: a loop closed on "round 11 spot-verify only" after a class-level fix, leaving the post-fix surface without its full fresh sweep).
- **Every dispatched finder has RETURNED and been adjudicated** — a round whose manifest shows `returned < dispatched` may be recorded but can NEVER be the exit round, and "covered by the orchestrator" is a NON-QUIET state: the orchestrator is the AUTHOR (measured 2026-09-02/03: self-coverage raised 3 candidates where the late finder raised 8, and a finder that returned AFTER a CONVERGED stamp carried a HIGH on the security surface — 01M1HATB, 01M1J5M0, 01M1J6K8, 01M1H82E). A finder still running is an OPEN question, not an absent one; a finder that DIED is re-dispatched. Nothing in the harness distinguishes slow from hung for you, so the loop waits or re-dispatches — it never closes over an outstanding finder.
- **Mechanical gates are green** (`final_gate`) — lint/type/test classes are the gates' job; do not spend finder passes re-discovering what a gate catches. **The gate section of the artifact is RE-MEASURED in the closing pass, never inherited** from an earlier pass's attribution — youtube 2026-09-03: pass 4 wrote "mypy stops before reaching anything this review wrote", pass 12 fixed the mypy config, and 23 passes then emitted a GATE line under an attribution their own pass 12 had invalidated (01M1J02D).
- **Ledger reproduced** — numbered passes with `found:` (counting every candidate RAISED that NEEDS adjudication — later-refuted FRESH candidates included; a re-raise of an already-adjudicated STANDING row is CITED in its disposition row, never counted — D-206), `new:` (candidates first raised THAT round — never raised, in any adjudication state, by an earlier round), `confirmed:` (candidates you EXECUTED and that held — the exit counter, D-206; the stall breaker below keys on it), `fixed:` and `unexecuted:` per pass, **and each row names its FINDERS** (which pool units + which native agents were dispatched for THAT round) **plus a `method` cell, written WITH its label (`method: citation` | `method: re-derivation` | `method: gate` — the graders anchor on the label). The CLOSING pass is a RE-DERIVATION pass — a different METHOD, not just a fresh read: re-derive every count, enumeration and anchor from its primary source, and the exit REQUIRES at least one row naming `method: re-derivation` — `check_review_coverage.py` (`_REDERIVATION_ROW`) HARD-BLOCKS any changed review artifact without one; convergence under a single method is method-stability, not truth.** A row with no finder manifest is not a pass. **The manifest counts dispatched AND returned — a finder that DIES (stream watchdog, API stall, null return) has swept NOTHING:** its partition stays un-swept until re-dispatched or covered by the orchestrator, and the row says so (`dispatched: 3, returned: 1, partitions re-covered: 2`). Silently counting a dead finder's partition as swept is how a review loses two-thirds of its recall and still stamps converged (web-ecommerce-factory, 2026-08-29: 5 finder deaths in one day at the harness's 600s no-progress watchdog, accumulated findings discarded — the survivor proved the work fits in ~260s, so the deaths were stalls, not oversized briefs). **A verification/spot-verify run is labelled `VERIFY`, never numbered as a pass** — writing `found: 0, fixed: 0` for a finder round that never ran is a FABRICATED row (live confession: "I labelled a verification run as a pass — that's a fabricated row, which is the thing the ledger exists to prevent"). Forged evidence is worse than an honest non-quiet exit, because the gates machine-read these rows.

**Minimum two full rounds, ALWAYS** — the round that first completes the checklist is never the exit round: a fresh, independent round (a closing round with a fresh non-authoring seat — a DELTA round where the consumer runs delta rounds, its own FULL confirming round otherwise, as the scope paragraph above assigns per consumer) must re-adjudicate it (and may re-open classes). Accuracy outranks pass-count.

**There is NO round ceiling.** While anything is still being raised, the next round is owed — 5, 15, 30 rounds; the loop runs until the exit conditions hold. **Stall circuit-breaker (measured non-progress is a VERDICT, never a reason for round N+1):** if 3 consecutive later rounds (whatever shape the scope paragraph above assigns the consumer) show non-decreasing **and nonzero** `confirmed:` counts, STOP and emit `## BLOCKED: NON-CONVERGENCE` naming the suspected foundation error (a design claim, a contract, the decomposition) — the defect lives UPSTREAM of the surface; re-ground it, then resume. This is NOT a ceiling: rounds stay unbounded while `confirmed:` is falling; a refute-everything round can never trip it (refuted candidates never count, D-206); an all-zero streak (`confirmed: 0 · fixed: 0 · unexecuted: 0` rounds — re-raised already-adjudicated candidates are cited in their rows, never counted, D-206) is CONVERGENCE, never a stall — the breaker measures CONFIRMED-defect pressure, and zero pressure is the goal state (oscillation is the per-finding 3-attempt escalation's job, below). The ONLY non-quiet stop a review FINDING may cause is a **BLOCKED escalation**: a specific finding that survived **3 consecutive fix attempts** (same test failing three times) → pause THAT finding, post it to the operator (Telegram / report `## BLOCKED` section naming the finding + the 3 attempts), and keep looping on everything else. (The safety HARD STOP below and the stall circuit-breaker above are the separate, non-finding exceptions.) An agent never self-exits with an "accepted risk" — unresolved means BLOCKED-and-escalated, visible to the operator, not declared away. Re-invoking this command on unchanged code re-adjudicates this SAME checklist — free-hunting outside it must be justified as a new class, which is a rubric gap to report. A delta seat's brief carries the previous seat's REFUTED list verbatim — a refuted candidate re-raised by a fresh seat costs a round for nothing. **Scope-growth stop:** when consecutive rounds' findings fall only inside code the change ADDED — the fix grew the surface — route that surface to `/fabrik-spec` and converge on the original diff; the loop converges a diff, it never designs one (01M2AJG97).

Run every owed pass **UNPROMPTED, inside THIS ONE invocation** — never end the turn with `UNCHECKED` rows or an unconfirmed fix for the operator to re-invoke. You return control EXACTLY ONCE: at the fully-adjudicated checklist. **The one exception is a safety HARD STOP** — you discover you are about to touch production / shared data or fire a destructive action against real data: halt immediately, even with `UNCHECKED` rows left. Safety outranks completing the loop; that halt is a legitimate stop, not an incomplete turn. **Context is never a reason to stop:** the harness AUTO-COMPACTS long conversations and the run continues in the same invocation — keep durable artifacts current and keep going; "low context" filed as BLOCKED is still the named violation, and a heavy remainder is dispatched to fresh subagents, never deferred. Post-compact, the SessionStart hook auto-injects a recent-context recap, and the `session-recall` MCP (`search_chats` / `get_chat`) recovers any detail the summary dropped — use it instead of re-deriving or guessing.
