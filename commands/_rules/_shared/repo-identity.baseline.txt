## Repo identity — resolve WHERE you are before any repo-dependent decision or git mutation ¦ In a linked worktree your repo IDENTITY is the MAIN checkout, derived as `MAIN=$(git worktree list --porcelain | sed -n '1s/^worktree //p')` (the first porcelain record is always the main worktree; `$COMMON` itself is a `.git` DIRECTORY, never a checkout) — a worktree of `/opt/fabrik` IS the hub; a worktree of a project IS that project
## Repo identity — resolve WHERE you are before any repo-dependent decision or git mutation ¦ Submodule: `git rev-parse --show-superproject-working-tree` printing a path means you are in a SUBMODULE — its identity is the submodule's OWN repo (`$TOP`); the superproject is a DIFFERENT repo — never edit upward into it (the cross-repo HARD STOP)
