 ¦ Large reads go to seats (D-363, § 4.9 finding 4). A read the lead would make of more than ~30 k tokens (~120 KB — a long spec or plan, the ACTIVE rules packs together, `agents-fabrik.md`, a fabrik-lib module tree, a prior transcript) goes to ONE seat per source — `Explore` for the repo, `fabrik-researcher` for the web — briefed with the QUESTION the read must answer, never "summarise this", and returning at most ~2 k tokens with every claim anchored `path:line`; a question with several parts is numbered in the brief, which tells the seat to answer the parts in order, each within its named share of that ~2 k, so a truncated return loses the tail, not the middle, and a part the return never reaches is asked again, never read as empty
 ¦ A Haiku seat pays from ~10 k tokens
 ¦ The lead re-reads only the anchored lines it will cite, and EXECUTES every claim it writes into the artifact: a summary is navigation, never evidence
 ¦ Cobra: the cheapest way to satisfy this is a summary with no anchors — a claim without its `path:line` is re-read by the lead, never cited
